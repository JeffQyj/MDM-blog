# 文章约束条件

> 必须遵守的硬性规范：格式、命名、流程。
>
> 优先级：最高 · 适用阶段：全程 · 依赖：无

## 规则优先级

:::important
当多条规则冲突时，按以下优先级处理：

1. **最高优先级**（**禁止违反**）：frontmatter 7 字段、文件命名格式、推送流程
2. **高优先级**（**强烈建议遵守**）：分类、标签数量、admonition 用法、推送前校验
3. **普通优先级**（**视情况调整**）：内容风格、表达手法

**用户明确要求与规则冲突时，以用户要求为准**，并在文章中标注例外。
:::

## 1. frontmatter 规范

所有博客文章必须包含以下 frontmatter 字段，且修改文章内容时无需修改 frontmatter 字段内容。

```yaml
---
title: 文章标题
published: YYYY-MM-DD          # 发布日期
description: 简短描述（建议 50-150 字）
tags: [标签1, 标签2]            # 数组形式
category: 分类名称                # 单个分类
draft: false                     # true 表示草稿
lang: zh_CN                      # 语言代码
---
```

### 1.1 字段格式要求

- 包裹符号必须为 `---`（三个连字符），不能使用 `----` 或其他符号
- 7 个必填字段：title、published、description、tags、category、draft、lang
- tags 为数组形式 `[]`，category 为字符串
- 所有字段值使用双引号或无引号，避免单引号

### 1.2 字段写作要求

| 字段            | 写作要求                                 |
| ------------- | ------------------------------------ |
| `title`       | 与文件名完全一致；避免书名号、感叹号                   |
| `published`   | 实际发布时间（非故事发生时间，回忆类故事在正文体现）           |
| `description` | 50-150 字；包含核心关键词；避免"！"和"？"以外的强调符号    |
| `tags`        | 数组，2-5 个；推荐中文 + kebab-case；同标签可跨文章复用 |
| `category`    | 必须是五类固定分类之一                          |
| `draft`       | 已发布文章为 `false`；草稿阶段为 `true`          |
| `lang`        | 固定 `zh_CN`                           |

## 2. 文件命名规范（最高优先级）

**根据用户提供的分类和主题内容，直接定义文件命名和标题，禁止自己创建标题**

**文件名称是什么，对应的标题就是什么**，统一使用以下命名格式，**一定确保遵从以下格式命名**：

```
文件名称：分类名称：[具体事件/阶段标题].md
title：分类名称：[具体事件/阶段标题]     #需要包含分类名称
```

### 2.1 标准示例

- `编程生涯：从Hello-World开始的编程之路.md`
- `二次开发：博客诞生日志.md`
- `成长碎记：2024年终总结.md`

### 2.2 字符规范

| 项目       | 规范                                   |
| -------- | ------------------------------------ |
| 分类与标题分隔符 | 强制使用全角冒号「：」                          |
| 空格处理     | 文件名内不使用半角空格；标题中需要空格时用全角空格「　」或破折号「——」 |
| 禁止字符     | `/ \ : * ? " < > \|` 等系统保留字符         |
| 标题长度     | 建议 30 字以内；超过 50 字应拆分副标题              |
| 中英混排     | 中文为主；技术名词可保留英文                       |

## 3. 文章存放位置

文章统一存放在 `src/content/posts/` 目录下。

子目录按需建立（如 `src/content/posts/ref/` 存放参考资料），但**文章本身**必须在 `posts/` 根目录或一级子目录下。

## 4. 文章分类与标签

### 4.1 五类固定分类

文章分类固定为五类：

| 分类   | 说明             |
| ---- | -------------- |
| 成长碎记 | 个人成长、学习感悟、生活记录 |
| 个人杂谈 | 游戏、影视、随想等非技术内容 |
| 二次开发 | 基于现有项目的二次开发经验  |
| 独立项目 | 从零到一的完整项目实战    |
| 编程生涯 | 编程技术学习笔记       |

### 4.2 标签数量

标签至少两个，至多五个。

### 4.3 标签命名建议

- 推荐中文（如「Spring Boot」而非 `spring-boot`）
- 多词标签用全角空格分隔
- 同一概念在不同文章中保持标签一致（避免「SpringBoot」「Spring Boot」「springboot」并存）
- 不使用纯英文标签（除非是专有名词如「JavaScript」）

## 5. 文章内容规范

### 5.1 禁止互动类内容

本项目暂无留言、评论功能，文章中**禁止出现**以下互动引导：

| 类型   | 示例                |
| ---- | ----------------- |
| 征求留言 | 「欢迎留言分享」「有问题欢迎留言」 |
| 征求意见 | 「如果你有更好的方法，欢迎提出」  |
| 提问读者 | 「你有没有遇到过这种情况？」    |
| 征集分享 | 「欢迎分享你的经历」        |

文章结尾仅允许使用静态引导，如「有问题可提 Issue」或「更多内容可查看 xxx」。

### 5.2 日期语义规范

- `published` 字段表示**文章发布的时间**，而非故事发生时间
- 若文章内容为回忆性质，「故事发生时间」应在正文中体现，不体现在 frontmatter
- 示例：回忆 2022 年的故事，published 应为实际发布时间（如 2025 年），正文开头写「2022 年的某天...」

## 6. 二次开发参考规则

二次开发类别文章撰写需要参考独立项目系列文章，确保内容深度与项目实战的连贯性。
