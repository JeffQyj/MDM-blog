# 文章约束条件

聚焦「**必须遵守的硬性规范**」——不可违反的格式、命名、流程。所有规则点来源于原 `project_rules1.md`、`project_rules2.md`、`project_rules3.md`、`project_rules5.md`，已重组去重。

---

## 1. frontmatter 规范

所有博客文章必须包含以下 frontmatter 字段，且修改文章内容时无需修改 frontmatter 字段内容。

```yaml
---
title: 文章标题
published: YYYY-MM-DD          # 发布日期
description: 简短描述（建议 50-150 字）
tags: [标签1, 标签2]            # 数组形式
category: 分类名称                # 单个分类
draft: false                     # true 表示草稿
lang: zh_CN                      # 语言代码
---
```

**格式要求**：

- 包裹符号必须为 `---`（三个连字符），不能使用 `----` 或其他符号
- 7 个必填字段：title、published、description、tags、category、draft、lang
- tags 为数组形式 `[]`，category 为字符串
- 所有字段值使用双引号或无引号，避免单引号

---

## 2. 文件命名规范（最高优先级）

**文件名称与标题名称采用相同标题**，统一使用以下命名格式，**一定确保遵从以下格式命名**：

```
分类名称：[具体事件/阶段标题].md
```

例如：

- `编程生涯：从Hello-World开始的编程之路.md`
- `二次开发：博客诞生日志.md`
- `成长碎记：2024年终总结.md`

---

## 3. 文章存放位置

文章统一存放在 `src/content/posts/` 目录下。

---

## 4. 文章分类与标签

### 4.1 五类固定分类

文章分类固定为五类：

| 分类   | 说明             |
| ---- | -------------- |
| 成长碎记 | 个人成长、学习感悟、生活记录 |
| 个人杂谈 | 游戏、影视、随想等非技术内容 |
| 二次开发 | 基于现有项目的二次开发经验  |
| 独立项目 | 从零到一的完整项目实战    |
| 编程生涯 | 编程技术学习笔记       |

### 4.2 标签数量

标签至少两个，至多五个。

---

## 5. 文章内容规范

### 5.1 禁止互动类内容

本项目暂无留言、评论功能，文章中**禁止出现**以下互动引导：

| 类型 | 示例 |
|------|------|
| 征求留言 | 「欢迎留言分享」「有问题欢迎留言」 |
| 征求意见 | 「如果你有更好的方法，欢迎提出」 |
| 提问读者 | 「你有没有遇到过这种情况？」 |
| 征集分享 | 「欢迎分享你的经历」 |

文章结尾仅允许使用静态引导，如「有问题可提 Issue」或「更多内容可查看 xxx」。

### 5.2 日期语义规范

- `published` 字段表示**文章发布的时间**，而非故事发生时间
- 若文章内容为回忆性质，「故事发生时间」应在正文中体现，不体现在 frontmatter
- 示例：回忆 2022 年的故事，published 应为实际发布时间（如 2025 年），正文开头写「2022 年的某天...」

二次开发类别文章撰写需要参考独立项目系列文章，确保内容深度与项目实战的连贯性。
