# 文章约束条件

## 1. frontmatter 规范

所有博客文章必须包含以下 frontmatter 字段，且修改文章内容时无需修改 frontmatter 字段内容。

```yaml
---
title: 文章标题
published: YYYY-MM-DD          # 发布日期
description: 简短描述（建议 50-150 字）
tags: [标签1, 标签2]            # 数组形式
category: 分类名称                # 单个分类
draft: false                     # true 表示草稿
lang: zh_CN                      # 语言代码
---
```

### 1.1 字段格式要求

- 包裹符号必须为 `---`（三个连字符）
- 7 个必填字段：title、published、description、tags、category、draft、lang
- tags 为数组形式 `[]`，category 为字符串
- 所有字段值使用双引号或无引号，避免单引号

### 1.2 字段写作要求

| 字段            | 写作要求                                 |
| ------------- | ------------------------------------ |
| `title`       | 与文件名完全一致                             |
| `published`   | 实际发布时间                               |
| `description` | 50-150 字；包含核心关键词                     |
| `tags`        | 数组，2-5 个；推荐中文 + kebab-case；同标签可跨文章复用 |
| `category`    | 必须是五类固定分类之一                          |
| `draft`       | 已发布文章为 `false`；草稿阶段为 `true`          |
| `lang`        | 固定 `zh_CN`                           |

## 2. 文件命名规范（最高优先级）

**根据用户提供的分类和主题内容，直接定义文件命名和标题，禁止自己创建标题**

**文件名称是什么，对应的标题就是什么**，统一使用以下命名格式，**一定确保遵从以下格式命名**：

```
文件名称：分类名称：[具体事件/阶段标题].md
title：分类名称：[具体事件/阶段标题] 
```

### 2.1 标准示例

- `编程生涯：从Hello-World开始的编程之路.md`
- `二次开发：博客诞生日志.md`
- `成长碎记：2024年终总结.md`

### 2.2 字符规范

| 项目       | 规范                                   |
| -------- | ------------------------------------ |
| 分类与标题分隔符 | 强制使用全角冒号「：」                          |
| 空格处理     | 文件名内不使用半角空格；标题中需要空格时用全角空格「　」或破折号「——」 |
| 禁止字符     | `/ \ : * ? " < > \|` 等系统保留字符         |
| 中英混排     | 中文为主；技术名词可保留英文                       |

## 3. 文章存放位置

文章统一存放在 `src/content/posts/` 目录下。

## 4. 文章分类与标签

### 4.1 五类固定分类

文章分类固定为五类：

| 分类   | 说明             |
| ---- | -------------- |
| 成长碎记 | 个人成长、学习感悟、生活记录 |
| 个人杂谈 | 游戏、影视、随想等非技术内容 |
| 二次开发 | 基于现有项目的二次开发经验  |
| 独立项目 | 从零到一的完整项目实战    |
| 编程生涯 | 编程技术学习笔记       |

### 4.2 标签数量

标签至少两个，至多五个。

### 4.3 标签命名建议

- 推荐中文（如「Spring Boot」而非 `spring-boot`）
- 多词标签用全角空格分隔
- 同一概念在不同文章中保持标签一致（避免「SpringBoot」「Spring Boot」「springboot」并存）

## 5. 文章内容规范

### 5.1 禁止互动类内容

本项目暂无留言、评论功能，文章中**禁止出现**互动引导。

文章仅允许使用静态引导，如「有问题可提 Issue」或「更多内容可查看 xxx」。

### 5.2 日期语义规范

- `published` 字段表示**文章发布的时间**

## 6. 文章内部链接规范（绝对遵守）

**唯一形式**：`[标题](../<slug>/)`，slug 是 Astro 生成的（小写英文、去除 `：` `——` `，` 等），**不是 Markdown 文件原名**。

链接示例：

```markdown
[从单体到微服务](../编程生涯从单体到微服务/) 
[Docker与容器化](../编程生涯docker与容器化/) 
```

分类归档页用 `../../archive/?category=成长碎记`。

## 7. 二次开发参考规则

二次开发类别文章撰写需要参考独立项目系列文章，确保内容深度与项目实战的连贯性。

## 8. 好书分享文章约束

「好书分享」是「个人杂谈」分类下的**内容子集**，通过 `tags: [好书分享, ...]` 标识，专供 `/bookshelf/` 书架页过滤展示。本节规范专门约束此类文章的封面图与命名。

### 8.1 封面图存放位置

封面图**不**与 .md 同目录，统一存放在中央目录 `src/assets/books/`，便于全站书封集中管理与检索。

| 项              | 规范                                                      |
| -------------- | ------------------------------------------------------- |
| 存放根目录          | `src/assets/books/`（与 `src/assets/images/` 平级，首次创建）     |
| 文件命名           | 使用**书名**（不含《》书名号）作为文件名，全角书名号省略                          |
| 文件格式           | 优先 **WebP**（推荐）；允许 JPG / PNG；Astro `Image` 组件会自动转码为现代格式 |
| 推荐分辨率          | **1200 × 1800 px**（2:3 长宽比，2x DPI 适配 retina 屏）          |
| 最小分辨率          | 600 × 900 px（避免高 DPI 屏糊图）                               |
| frontmatter 写法 | `image: <书名>.webp`（相对 `src/assets/books/` 的文件名）         |
| 组件参数           | `BookCard.astro` 固定传入 `basePath="assets/books/"`        |

**示例**（以《被讨厌的勇气》为例）：

```text
src/
└── assets/
    └── books/
        └── 被讨厌的勇气.webp    ← 封面图

src/content/posts/
└── 个人杂谈：《被讨厌的勇气》.md  ← 对应文章
```

对应 frontmatter示例：

```yaml
---
title: 个人杂谈：《被讨厌的勇气》
published: 2026-06-10
description: 一本能让你重新定义「自由」与「幸福」的阿德勒心理学入门书——…
tags: [好书分享, 个人杂谈, 心理学]
category: 个人杂谈
image: 被讨厌的勇气.webp
draft: false
lang: zh_CN
---
```

### 8.2 封面图适配策略

| 维度       | 规范                                           |
| -------- | -------------------------------------------- |
| 容器宽高比    | 固定 `aspect-ratio: 2 / 3`（业界书封主流比例，竖向）        |
| 图片填充模式   | `object-fit: cover`（裁切以填满容器，绝不露白）            |
| 裁切锚点     | `object-position: center`（默认居中裁切）            |
| 容器背景     | 浅金色渐变（占位底色，图片加载前可见）                          |
| hover 效果 | 图片轻微缩放 `transform: scale(1.03)` + 烫金描边加深 2px |
| **缺图降级** | 当 `image` 为空或文件不存在时，渲染「书脊 + 占位标题」兜底条（保持双列等高） |

:::important
好书分享文章应使用 **2:3 长宽比**的封面图，且**关键视觉元素（书名、作者）应位于图片中心区域**。若原图非 2:3，请预先裁切/加白边到 2:3 再上传。
:::

## 9. 延伸阅读规范

每篇文章结尾必须包含 **「延伸阅读」** 板块，用于引导读者跳转相关文章。

### 9.1 格式要求

```markdown
**延伸阅读：**

- [文章标题](../文章slug/) — 一句话简述文章核心内容
```

### 9.2 内容规则

- **数量**：3~6 个链接
- **内容**：本站博客文章链接，或外部相关官网及资源链接
- **排序**：按与本文内容的时间相关性从近到远排列
- **简述**：每次必写，不超过 20 字，用「—」分隔
- **slug 规则**：遵循第 6 节内部链接规范，使用 Astro 生成的 slug，**禁止**使用 Markdown 文件原名

### 9.3 位置

位于**结尾感悟段之后**，文章最后一行之前。
