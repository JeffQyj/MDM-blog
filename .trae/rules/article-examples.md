# 文章正反例库

## 1. 风格正反例

### 1.1 比喻使用

| ❌ 不推荐                | ✅ 推荐                                   |
| -------------------- | -------------------------------------- |
| "Redis 是个 NoSQL 数据库" | "Redis 像一个超快的快递柜，存取毫秒级"                |
| "JWT 用于身份验证"         | "JWT 像一张盖了章的通行证，证明你是你"                 |
| "Nginx 是反向代理服务器"     | "Nginx 像大楼门口的保安，帮你把请求转发到对应楼层"          |
| "Docker 是容器化技术"      | "Docker 像标准化的集装箱，让你的应用无论换哪艘船（服务器）都能跑"  |

| "数据库索引是 B+ 树"        | "数据库索引像一本书的目录，让你不用翻完整本书就能找到对应内容"       |

| ❌ 不推荐       | ✅ 推荐                               |

| ❌ 不推荐               | ✅ 推荐                                              |

## 2. 结构正反例

### 2.1 admonition 用量

| 场景              | ❌ 不推荐                         | ✅ 推荐                 |
| --------------- | ----------------------------- | -------------------- |
| 长文章无 admonition | 全文 5000 字一个 `:::` 都没有，读者抓不到重点 | 5 种类型各用 1-3 次，关键提示醒目 |
| admonition 泛滥   | 每段都用 `:::`，反而稀释语义             | 仅在确实需要强调/警示/补充处使用    |
| 滥用 `warning`    | 把常识性提醒写成 `warning`            | `warning` 仅用于真正严重的风险 |

### 2.2 标题层级

| ❌ 不推荐                   | ✅ 推荐                                          |
| ----------------------- | --------------------------------------------- |
| `# 标题` → `#### 子标题`（跳级） | `# 标题` → `## 大节` → `### 小节` → `#### 细节`（逐级递进） |
| 章节下没有子标题直接堆段落           | 用 2-3 个 `###` 子标题拆分                           |
| 一级标题当章节名（多个 `#`）        | 全文仅 1 个 `#` 作文章标题，章节用 `##`                    |

### 2.3 段落与列表

| ❌ 不推荐                        | ✅ 推荐              |
| ---------------------------- | ----------------- |
| 一段话 200 字不分段                 | 每 3-5 句分段，或转为列表   |
| 列举 3 件事用一段话"首先...其次...最后..." | 用有序/无序列表          |
| 列表项全是完整句子                    | 列表项尽量简洁短语，省略主语/动词 |

## 3. 代码正反例

### 3.1 注释丰富度

| ❌ 不推荐                                                  | ✅ 推荐                                                                                                        |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `js\nconst a = 1;\nconst b = 2;\nconst sum = a + b;\n` | `js\n// 计算两个数的和\nconst a = 1;        // 第一个加数\nconst b = 2;        // 第二个加数\nconst sum = a + b;  // 求和结果\n` |
| 代码块无任何注释                                               | 关键业务逻辑、参数含义、特殊处理都加注释                                                                                        |
| 注释全是废话（`// 循环` 在 for 循环上）                              | 注释解释「为什么」而非「是什么」                                                                                            |

### 3.2 代码块语言标签

| ❌ 不推荐                         | ✅ 推荐                                           |
| ----------------------------- | ---------------------------------------------- |
| ` ``` `（无标签）                  | ` ```typescript ` / ` ```bash ` / ` ```sql ` 等 |
| ` ```js ` 用于 JSON             | ` ```json `                                    |
| ` ```shell ` 与 ` ```bash ` 混用 | 项目内统一用 ` ```bash `                             |

### 3.3 错误处理代码

```typescript
// ❌ 不推荐：吞掉错误
try {
  await fetchData();
} catch (e) {
  // 啥也不做
}

// ✅ 推荐：记录 + 友好提示
try {
  await fetchData();
} catch (e) {
  console.error('[fetchData] 失败:', e);
  throw new Error('数据加载失败，请稍后重试');
}
```

### 3.4 命名规范

| ❌ 不推荐                             | ✅ 推荐                                        |
| --------------------------------- | ------------------------------------------- |
| `let a = 1;`                      | `let userCount = 1;`                        |
| `function fn(x, y) {}`            | `function calculateSum(price, quantity) {}` |
| `const DATA = []`（应使用 `let` 因为会变） | `let cachedData = []`                       |
| 中文变量名                             | 英文命名；注释补充含义                                 |

## 4. 独立项目正反例

### 4.1 技术深度

| ❌ 不推荐                | ✅ 推荐                                                                               |
| -------------------- | ---------------------------------------------------------------------------------- |
| "用 Spring Boot 写了后端" | "用 Spring Boot 3.2 + Spring Security 6 实现 JWT 鉴权；MyBatis-Plus 处理 ORM；Redis 缓存用户会话" |
| 列举 20 个技术栈但都只提名字     | 选 5-8 个核心技术栈，每个配通俗比喻和 1-2 句说明                                                      |
| 全文无架构图               | 必有 1-2 张架构图（ASCII / mermaid / HTML 表格）                                             |

### 4.2 业务模块选择

| ❌ 不推荐              | ✅ 推荐                         |
| ------------------ | ---------------------------- |
| 把 20 个 CRUD 模块都讲一遍 | 选 2-6 个最有代表性的（认证、搜索、关系、文件型等） |
| 只讲自己写得最熟的部分        | 模块类型尽量多样（CRUD + 认证 + 状态机）    |
| 模块讲解只贴代码           | 每个模块配「业务场景 + 核心代码 + 技术要点」    |

### 4.3 踩坑实录

| ❌ 不推荐         | ✅ 推荐                       |
| ------------- | -------------------------- |
| "踩了一些坑，最后解决了" | 现象 → 根因 → 方案 → 总结，每步都有具体内容 |
| 解决方案只有文字描述    | 必须包含可复制的配置/代码片段            |
| 总结空话"以后要注意"   | 总结出可迁移的判断标准或最佳实践           |
