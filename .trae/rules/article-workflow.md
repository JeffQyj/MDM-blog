# 文章工作流

## 决策表

:::tip
**用户输入 → AI 行为**的速查表，AI 在响应前必查。
:::

| 用户输入 | AI 行为 |
| --- | --- |
| 仅提供主题 | 进入 §2 大纲生成阶段 |
| 提供主题 + "参考 X 文章" | 检索 X 文章，§2 大纲中体现 |
| 反馈"修改第 N 章节大纲" | 回到 §2 优化该章节大纲 |
| 反馈"确认大纲" / "可以了" | 进入 §3 创作 |
| 反馈"第 N 段重写" / "扩充 X" | 回到 §3 局部重写 |
| 反馈"内容无误" | 进入 §4 校验 |
| 反馈"打回" / "重写 X" | 回到 §3 重写对应章节 |
| 反馈"推送" / "提交" | 执行推送流程 |
| 反馈"修个错别字" / "链接失效" | 走 §7 紧急修改流程 |

## 1. 主题与要求确认

当用户提供博客主题后，明确用户附带的文章要求，**技术文章一定要联网查证保证绝对正确**，而非直接生成。

## 2. 大纲生成与优化

:::important
**核心规则**：在用户明确发出确认大纲的指令之前，只做大纲优化和完整大纲呈现，**不创作正文**。用户确认后，方可进入 §3 创作。
:::

### 2.1 具体行为

- 接收用户的主题或反馈后，**仅做大纲优化和完整大纲呈现**
- 大纲需包含完整 frontmatter（title / published / description / tags / category / draft / lang）
- 附带文章优化的方案选择，供用户决策
- **不调用 `article-writing` 技能、不撰写正文**

### 2.2 大纲回退处理

若用户对大纲提出修改意见：调整后**重新呈现完整大纲**（不只展示修改部分），等待用户再次确认。

## 3. 文章创作

用户发出"确认大纲"或等同指令后，方可进入创作阶段。

### 3.1 具体行为

- 调用 `article-writing` 技能进行文章撰写
- **参考 4 篇及以上同分类内容相关的文章**，优先选取日期相近的文章；系列文章需全部参考
- 同时参考其他分类有内容相关性的文章；**内容有相关性的需自然呼应**，禁止完全重复
- 提供的资料参考要**完整读取、绝对参考**，杜绝幻觉与编造

### 3.2 对抗性审查

每节完成后，立即从以下维度自我审查，审查结果以 `caution` / `warning` admonition 形式融入正文：

1. **极端场景**：当前方案在高并发、网络异常等极端条件下是否会崩溃？补充避坑指南或限制条件
2. **逻辑漏洞**：是否有未经证实的断言？是否有因果倒置？
3. **替代方案**：为什么推荐当前方案而非竞品？客观补充当前方案的缺点（Trade-offs）

## 4. 文章校验

:::important
**核心规则**：只有用户确认文章内容无误后，才执行以下校验。
:::

### 4.1 校验内容

1. **代码校验**：运行 `pnpm check` 检查类型错误；必要时运行 `pnpm format` 进行代码格式化
2. **规则符合性自检**：对照 `article-constraints.md` 与 `article-style.md` 检查命名、分类、标签数量、禁止内容、风格等

### 4.2 校验失败处理

| 失败类型 | 处理方式 |
| --- | --- |
| `pnpm check` 报错 | 报告错误位置与原因，**等待用户决策** |
| `pnpm format` 改动 | 自动应用，记录改动位置 |
| 规则违反（如分类错误） | 报告违规点，**等待用户决策** |

## 5. 输出格式

完成大纲确认后，最终返回文章时输出以下概要：

```text
**文章概要：**
| 属性 | 内容 |
| --- | --- |
| 标题 | xxx |
| 发布日期 | YYYY-MM-DD |
| 分类 | xxx |
| 标签 | xxx |
| 篇幅 | 约 xxx 字 |
```
