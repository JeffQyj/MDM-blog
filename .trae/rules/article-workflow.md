# 文章工作流

聚焦「**与用户协作的工作流规范**」——阶段划分、确认机制。所有规则点来源于原 `project_rules1.md`、`project_rules2.md` 中关于生成流程的描述，并按用户明确要求的工作流重新组织。

---

## 1. 主题与要求确认

当用户提供博客主题后，明确用户附带的文章要求，**技术文章一定要联网查证保证绝对正确**，而非直接生成。

---

## 2. 大纲生成与优化

> **核心规则：在用户未明确发出确认大纲的指令之前，发送的所有内容都是为了优化大纲。**
>
> 你只需要根据用户发送的内容进行大纲优化和完整大纲的呈现，**不创作正文**。

具体行为：

- 接收用户的主题或反馈后，**仅做大纲优化和完整大纲呈现**
- 大纲需包含完整 frontmatter（title / published / description / tags / category / draft / lang）
- 附带文章优化的方案选择，供用户决策
- **不调用 `article-writing` 技能、不撰写正文**
- 不得在未确认大纲前输出文章内容

---

## 3. 文章创作

> **核心规则：只有在用户明确发出确认大纲的命令之后，才开始创作文章。**
>
> 用户发出"确认大纲"或等同指令后，方可进入创作阶段。

具体行为：

- 调用 `article-writing` 技能进行文章撰写
- **参考 3 篇及以上同分类、内容相关的文章**，并根据 frontmatter 日期字段优先选取日期相近的同分类文章
- 同时参考其他分类有内容相关性的文章
- **内容有相关性时需要进行呼应**：呼应不允许完全重复，而是另起一种类似的说法，呼应不应生硬，需要自然融入文章内容
- 提供的资料参考要**完整读取**，根据资料序号进行大纲生成，**杜绝幻觉**
- 提供的内容参考要**绝对参考**，仅进行优化润色和丰富，**杜绝编造**
- 独立项目系列文章还需与发布时间在此之前的系列文章进行联动

---

## 4. 文章校验

> **核心规则：只有用户确认文章内容无误后，才进行文章校验。**
>
> 用户发出"内容无误"或等同指令后，方可执行以下校验。

校验内容：

1. **frontmatter 格式校验**：包裹符号、7 个必填字段、tags 数组形式、引号规范
2. **代码校验**：运行 `pnpm check` 检查类型错误；必要时运行 `pnpm format` 进行代码格式化
3. **规则符合性自检**：对照 `article-constraints.md` 与 `article-style.md` 检查命名、分类、标签数量、禁止内容、风格等

---

## 5. 输出格式

完成大纲确认后，最终返回文章时输出以下概要：

```
**文章概要：**
| 属性 | 内容 |
|------|------|
| 标题 | xxx |
| 发布日期 | YYYY-MM-DD |
| 分类 | xxx |
| 标签 | xxx |
| 篇幅 | 约 xxx 字 |
```

---

## 6. 工作流速查

| 阶段      | 触发条件                  | 主要动作                  | 禁止动作            |
| ------- | --------------------- | --------------------- | --------------- |
| 大纲生成与优化 | 用户给出主题/反馈             | 大纲优化、完整大纲呈现、方案选择     | 撰写正文            |
| 文章创作    | 用户明确确认大纲              | 调用 article-writing 撰写正文 | 跳过大纲确认          |
| 文章校验    | 用户明确确认文章内容无误          | frontmatter 校验、`pnpm check` | 未经用户确认就执行校验    |
| 推送      | 用户明确发出推送指令            | git status → check → format → add → commit → push | 未经用户指令就执行推送    |
