# 实施方案：新增「项目」页面（工程蓝图风格）

## Summary

在导航栏「精选」与「关于」之间新增 **项目** 页面（路由 `/projects/`），聚合展示 `category` 为「独立项目」与「二次开发」的全部文章（共 13 篇）。页面采用 **工程蓝图/技术制图** 美学：栅格纸背景、技术字体、项目代号、状态指示灯、技术栈芯片，配合客户端分类筛选器，呈现「项目档案总览」的工程仪表盘感。

---

## Phase 1 探索结论

| 维度        | 结论                                                                                                          |
| --------- | ----------------------------------------------------------------------------------------------------------- |
| 页面路由      | 仿照 `featured.astro` / `archive.astro`，新建 `src/pages/projects.astro`                                       |
| 导航注册      | 走 `LinkPreset` 枚举扩展（已存在 Home/Archive/About/Featured 四个枚举值）                                                |
| 国际化       | 10 种语言文件均需补 `projects` 键（参考 `featured` 现有写法）                                                                |
| 文章筛选      | 在 `content-utils.ts` 新增 `getProjectPosts()`，复用 `getRawSortedPosts()` 过滤两分类                              |
| 卡片复用      | **不复用** `FeaturedCard.astro`；新建项目专用 `ProjectCard.astro`，更契合工程制图风格                                          |
| 客户端筛选     | 14 篇量级无需分页，用 Svelte 5 组件 `ProjectsFilter.svelte` 处理分类切换（与 `ArchivePanel.svelte` 方案一致）                       |
| 设计系统      | 严格遵循现有 `oklch + var(--hue)`、`--primary`、`--btn-*` 主题变量；亮/暗双模自动适配                                         |

## Design Vision：工程蓝图（Engineering Blueprint）

### 美学关键词
- **Cad/Schematic 制图感**——栅格纸、坐标轴、角标（┌ ┐ └ ┘）、尺寸标注线
- **技术排版**——JetBrains Mono（项目代号/技术栈）+ Syne（标题，强辨识度展示字体，避免 Inter）
- **状态语义**——LED 指示灯、DEPLOYED/ACTIVE/ARCHIVED/DRAFT 四态
- **冷色主调 + 紫色 accent**——继承 `--primary` 紫色作为强调，工程蓝（cyan）作为辅助信号色

### 排版方案
| 用途            | 字体栈                                                                    |
| ------------- | ---------------------------------------------------------------------- |
| 大标题（H1）       | `"Syne", "Noto Serif SC", sans-serif`（字重 800，tracking 收紧）             |
| 副标题/段头（eyebrow） | `"JetBrains Mono Variable", ui-monospace, monospace`（全大写 + letter-spacing） |
| 卡片标题          | `"Syne", "Noto Serif SC", sans-serif`（字重 700）                       |
| 项目代号/技术栈/状态   | `"JetBrains Mono Variable", ui-monospace, monospace`                   |
| 正文描述          | 系统默认无衬线，继承全局字号                                                      |

> 注：Syne 字体通过 Google Fonts 引入（仅在 `projects.astro` 局部 head 注入），避免污染全站。

### 配色（在现有主题变量基础上扩展）
| Token                   | 用途              | 值（亮 / 暗）                                                 |
| ----------------------- | --------------- | ------------------------------------------------------- |
| `--primary`（已存在）      | 强调色、按钮          | 沿用                                                      |
| `--blueprint-line`（新增）  | 栅格线/标注线         | `oklch(0.55 0.02 var(--hue) / 0.18)` / `0.7 ... / 0.18` |
| `--blueprint-accent`（新增） | 状态 LED、坐标轴箭头     | `oklch(0.78 0.16 220)`（cyan-电光蓝，不随 hue 变化）              |
| `--blueprint-deployed`（新增） | DEPLOYED 状态     | `oklch(0.72 0.18 145)`（绿）                              |
| `--blueprint-archived`（新增） | ARCHIVED 状态     | `oklch(0.55 0.02 var(--hue))`（灰）                         |
| `--blueprint-draft`（新增）   | DRAFT 状态        | `oklch(0.72 0.18 65)`（琥珀）                               |

### 核心视觉元素
1. **栅格背景**——`linear-gradient` 双向重复，形成 24px×24px 细网格 + 120px×120px 粗网格（双层叠加）
2. **角标（Corner Brackets）**——`::before/::after` 伪元素在卡片四角绘制 ┌ ┐ └ ┘ 形式的 L 形线条
3. **项目代号**——`PRJ.YYYY.NNN` 格式（NNN 按 published 倒序编排）
4. **状态 LED**——6px 圆形 + 外发光光晕（CSS `box-shadow` 多层叠加，ACTIVE 状态 2s 慢呼吸动画）
5. **技术栈芯片**——sharp 圆角（2px）、等宽字体、左上小方块装饰点
6. **尺寸标注线**——卡片顶部一条「scale bar」样式的水平线 + 刻度
7. **Hero 数据条**——用 ASCII 风格表格呈现统计信息（`TOTAL PROJECTS / DEPLOYED / TECH STACKS / LAST BUILD`）

## Proposed Changes

### 1. i18n 新增 `projects` 键
**文件**：`src/i18n/i18nKey.ts`
- 在 `featured` 后追加 `projects = "projects"`
- 所有 10 个语言文件追加翻译（参照 `featured` 一致命名风格）

| 语言       | 翻译                            |
| -------- | ----------------------------- |
| zh_CN    | 项目                            |
| zh_TW    | 專案                            |
| en       | Projects                      |
| ja       | プロジェクト                       |
| ko       | 프로젝트                         |
| es       | Proyectos                     |
| th       | โปรเจกต์                       |
| vi       | Dự án                         |
| id       | Proyek                        |
| tr       | Projeler                      |

**Why**：保持与现有 `featured/archive` 命名一致，i18n 缺失会回退到英文。

### 2. 扩展 `LinkPreset` 枚举
**文件**：`src/types/config.ts`
```ts
export enum LinkPreset {
    Home = 0,
    Archive = 1,
    About = 2,
    Featured = 3,
    Projects = 4,  // 新增
}
```
**Why**：枚举值必须显式定义才能在 `LinkPresets` 字典中注册。

### 3. 注册导航预设
**文件**：`src/constants/link-presets.ts`
- 追加 `[LinkPreset.Projects]: { name: i18n(I18nKey.projects), url: "/projects/" }`

**Why**：导航链接数据源。

### 4. 调整导航栏顺序
**文件**：`src/config.ts`
- `navBarConfig.links` 中在 `LinkPreset.Featured` 与 `LinkPreset.About` 之间插入 `LinkPreset.Projects`
- 顺序：Home → Archive → Featured → **Projects** → About → GitHub

**Why**：满足用户需求"在精选和关于之间新增"。

### 5. 新增文章筛选工具
**文件**：`src/utils/content-utils.ts`
- 新增 `getProjectPosts(): Promise<CollectionEntry<"posts">[]>`：
  - 调用 `getRawSortedPosts()` 后过滤 `data.category === "独立项目" || data.category === "二次开发"`
  - 返回完整 entry（含 body）供组件在构建时调用 `entry.render()` 取 excerpt/minutes
- 在 `PostForList` 之后导出 `ProjectPost = { entry, remarkPluginFrontmatter }` 类型

**Why**：与 `getFeaturedPosts()` 模式对齐，参考文章已有 13 篇，复用现成函数避免重复 IO。

### 6. 新增页面文件
**文件**：`src/pages/projects.astro`
```astro
---
import ProjectsPanel from "@components/ProjectsPanel.astro";
import I18nKey from "@i18n/i18nKey";
import { i18n } from "@i18n/translation";
import MainGridLayout from "@layouts/MainGridLayout.astro";
import { getProjectPosts } from "../utils/content-utils";

const projectPosts = await getProjectPosts();
---
<MainGridLayout title={i18n(I18nKey.projects)} description="项目档案：独立项目与二次开发全集">
    <ProjectsPanel posts={projectPosts}></ProjectsPanel>
</MainGridLayout>
```

**Why**：与 `featured.astro` / `archive.astro` 模式完全一致，最小化集成成本。

### 7. 新增页面主组件
**文件**：`src/components/ProjectsPanel.astro`

**结构**：
- **Props**：`posts: CollectionEntry<"posts">[]`
- **数据预处理**：`await Promise.all(posts.map(async e => ({ entry: e, ...await e.render() })))`
- **派生计算**：
  - `projectStats`：总篇数、各分类计数、技术栈（tags）去重集合、最近发布日期
  - `serialMap`：将 posts 按 published 倒序映射 `PRJ.YYYY.NNN`（NNN 从 001 起补零）
  - `statusMap`：根据 `draft` 与发布时间计算 DEPLOYED / ACTIVE / ARCHIVED / DRAFT
- **三段渲染**：
  1. `<section class="projects-hero">`——栅格背景 + 数据条
  2. `<ProjectsFilter.svelte>`——分类筛选条
  3. `<section class="projects-grid">`——调用 `ProjectCard.astro` 渲染卡片

**样式要点**（全部 scoped）：
- `.projects-hero`：`background-image: linear-gradient(...) , linear-gradient(...)` 双向栅格 + 顶部高光 + 角部 L 形装饰
- 入场动画：参考 `FeaturedPanel` 的 `heroFadeIn` + `fadeUp`
- 移动端：栅格 1 列，hero 内边距收缩

**Why**：与 `FeaturedPanel.astro` 的拆分粒度一致，方便阅读和维护。

### 8. 新增筛选组件（Svelte 5）
**文件**：`src/components/ProjectsFilter.svelte`

**职责**：
- 接收 `categories: { name: string; count: number; all: number }` props
- 维护 `activeCategory: 'ALL' | '独立项目' | '二次开发'` 状态
- 维护 `sort: 'newest' | 'oldest'` 状态
- 渲染三组筛选 chip + 排序下拉
- 通过 `data-*` 属性 + `display: none` 切换卡片可见性（**不重新渲染**，性能更优）
- 状态写入 `localStorage` 持久化（参考 `DisplaySettings` 已有做法）

**Why**：筛选逻辑放 Svelte 是项目既定模式（`ArchivePanel.svelte`），避免污染 Astro 静态构建。

### 9. 新增项目卡片组件
**文件**：`src/components/ProjectCard.astro`

**Props**：
```ts
interface Props {
    entry: CollectionEntry<"posts">;
    projectCode: string;       // "PRJ.2024.001"
    status: "DEPLOYED" | "ACTIVE" | "ARCHIVED" | "DRAFT";
    techStack: string[];       // 从 tags 取前 4
    index: number;             // 序号（用于动画 delay）
}
```

**渲染结构**（详见 Design Vision 卡片部分）：
- 四角 L 形角标
- 顶部条形：「`PRJ.2024.001` · DEPLOYED ●」
- 大标题（Syne 字体）
- 描述（2 行截断）
- 底部：技术栈芯片 + 日期 + READ 圆形按钮
- 悬停：轻微 translateY + LED 灯闪烁 + 角标延长

**状态判定规则**（与 `ProjectsPanel` 中 `statusMap` 同步）：
| 条件         | 状态        |
| ---------- | --------- |
| `draft=true` | DRAFT     |
| 距今 ≤ 6 个月  | ACTIVE    |
| 距今 ≤ 24 个月 | DEPLOYED  |
| 其余         | ARCHIVED  |

### 10. 引入 Syne 字体
**文件**：`src/layouts/Layout.astro` 内的 `<head>`
- 仅在 `Astro.url.pathname === '/projects/'` 时动态注入 Syne 字体 link
- 使用 `<link rel="preconnect">` + `<link rel="stylesheet">` 异步加载

**Why**：避免全站加载导致首屏 LCP 下降，按需加载契合「项目页是少数高设计感页面」的定位。

## Assumptions & Decisions

| 决策点                  | 选择                                       | 理由                                                                       |
| -------------------- | ---------------------------------------- | ------------------------------------------------------------------------ |
| 路由路径                 | `/projects/`                             | 复数形式，契合"项目集合"语义；与 `/featured/`、`/archive/` 风格一致                                 |
| 命名空间                 | `LinkPreset.Projects`                    | 走枚举扩展而非内联配置，便于后续 i18n 切换                                                  |
| 排序逻辑                 | 客户端可切换（最新/最早）                          | 项目时间跨度大（2024-2026），给用户筛选权                                                  |
| 状态机                 | DEPLOYED/ACTIVE/ARCHIVED/DRAFT 四态         | 完整覆盖文章生命周期，与工程师心智模型一致                                                   |
| 卡片信息维度              | 项目代号 + 状态灯 + 标题 + 描述 + 技术栈芯片 + 日期 + READ  | 用户已确认"增强型"；技术栈从 tags 复用，避免文章改造                                       |
| 是否复用 FeaturedCard    | 否                                        | 视觉语言不同（杂志感 vs 工程蓝图），强行复用会牺牲辨识度                                          |
| 是否新建 component 目录   | 否                                        | 按项目惯例全部放 `src/components/` 根目录（与 `FeaturedCard.astro`、`FeaturedPanel.astro` 一致） |
| 是否新增 14 篇项目外的内容   | 否                                        | 仅聚合现有 13 篇文章，不新增示例/占位项目                                                  |
| 国际化范围               | 10 种语言全量补齐                              | 缺失会触发 `defaultTranslation = en` 回退，但保持仓库一致性                                    |
| 状态持久化                | `localStorage` 记忆分类选择                  | 用户切换分类后刷新页面不应丢失                                                           |
| 是否添加暗色模式独立调色        | 否                                        | 全部走现有 `:root.dark` 覆盖，亮/暗双模自动适配                                            |
| 不修改的内容              | posts 目录中所有文章 frontmatter、GlobalStyles、Layout、astro.config | 严格控制改动面，最小化风险                                                              |

## Verification

1. **类型检查**：`pnpm check` 必须通过（无 TS 报错）
2. **代码规范**：`pnpm format` + `pnpm lint` 必须无错（Biome 校验）
3. **构建验证**：`pnpm build` 必须成功（验证 SSG 静态生成 13 张项目卡）
4. **本地预览**：`pnpm preview` 后浏览器访问 `/projects/`
   - 验证：① 导航栏出现"项目"且位置在精选和关于之间；② 13 张卡片正确渲染；③ 分类切换只显示对应文章；④ 刷新页面后筛选状态保留；⑤ 亮/暗主题均无视觉错位；⑥ 移动端 1 列布局正常
5. **内部链接巡检**：抽查若干卡片点击跳转目标文章 URL 正确
6. **i18n 巡检**：切换 `siteConfig.lang`（如临时改为 `en`）验证导航显示 "Projects"
7. **可访问性自查**（轻量）：所有交互元素具备 `aria-label`；LED 状态用文字 + 颜色双重表达
