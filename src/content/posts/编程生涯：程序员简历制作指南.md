:::tip
一份简历平均被浏览 10 秒。HR 不是"阅读"简历，而是"扫描"简历——他们带着关键词清单，快速判断你是否匹配。

简历的本质，是技术能力的浓缩展示，不是人生履历的流水账。2026 年的今天，AI 已经从加分项变成了筛选条件。你的简历上如果还没有任何 AI 相关的能力体现，很可能第一轮就被筛掉了。
:::

## 一、简历的核心五准则

动笔之前，先记住五条铁律。它们决定了你简历的整体走向。

| 准则 | 要求 | 为什么 |
|------|------|--------|
| 严格 1 页 | 只保留技术相关内容，删除社团、文娱、主观自评套话 | 面试官没有耐心翻到第二页 |
| 技术优先 | 实习经历 > 项目经验 > 技术技能 > 教育背景 | 技术能力才是核心评判标准 |
| ATS 兼容 | 纯文本单栏，无图片/二维码/证件照，导出文本型 PDF | HR 的简历筛选系统可能无法解析复杂格式 |
| 量化思维 | 每条经历都有技术动作 + 数据/规模 | 量化比定性更有说服力 |
| AI 关键词 | 简历中必须出现 AI 相关技能或项目 | AI 已成筛选条件，不是加分项 |

:::important
第五条可能是 2026 年简历最大的变化。随便翻翻现在大厂的 JD，很多都明确写着"熟悉 AI 大模型开发优先""有 AI 编程经验优先"。

如果你的简历上还是清一色的 CRUD 项目，一个 AI 相关的关键词都没有，那大概率在关键词匹配阶段就被过滤掉了。
:::

## 二、个人信息模块

个人信息只保留刚需字段，不额外加任何内容。

```
姓名
电话：XXX | 邮箱：XXX
GitHub/Gitee：https://xxx | 个人网站：https://xxx
意向城市：XXX
求职意向：XX 开发实习生 / XX 工程师
到岗时间：随时到岗 | 每周 X 天 | 可实习 X 个月
```

有两个容易被忽略的细节：

**第一，链接必须带协议头。** 写成 `Gitee：gitee.com/wangxx` 的话，导出 PDF 后很多阅读器无法识别为超链接。统一使用完整 URL：`https://gitee.com/wangxx`。

**第二，求职意向括号标注 AI 经验。** 比如"Java 后端开发（具备 AI Agent 全栈开发经验）"。HR 筛简历就像刷短视频，开头 3 秒没抓住注意力就直接划走了。既然你有 AI 相关经验，就要在最显眼的位置写清楚。

:::note
实习生建议补充到岗信息：`到岗时间：随时到岗 | 每周可出勤 5 天 | 可实习 6 个月以上`。HR 非常关心"你什么时候能来、能待多久"，写清楚能提高简历通过率。应届生全职求职可忽略这条。
:::

## 三、教育背景与奖项

格式：`学校 | 学历 | 专业 | 就读时间`

教育背景和奖项建议合并成一个板块。对于大多数同学来说，教育背景就一行，奖项也就一两行，没必要分成两个板块。

补充内容二选一：

| 场景 | 写什么 | 示例 |
|------|--------|------|
| 应届生常规版 | 仅加技术相关主修课程 | `主修课程：Java 开发、Web 前端、数据库原理、计算机网络` |
| 有技术奖项 | 保留奖项，删除杂项课程 | `奖项：校级程序设计竞赛二等奖` |

几个要点：
- 成绩排名前 20% 以上才写，不好看就不写
- 奖项按含金量和相关度排序，不知名比赛不写
- 专升本多段学历倒序排列，主修课程只放与求职最相关的一段

```text
XX 大学 | 本科 | 计算机科学与技术 | 2025-09 ~ 2027-06
XX 职业技术学院 | 专科 | 软件技术 | 2022-09 ~ 2025-06
主修课程：Java 开发、数据库原理、计算机网络
```

## 四、技术摘要

技术摘要是简历的"摘要标签"，2-3 行，拒绝任何虚话。

**公式：身份 + 核心技术栈 + 项目实战方向 + 个人能力亮点**

以下是三种场景的示例：

```text
软件技术专业在校生，熟练使用 Java、Spring Boot、MySQL，
独立完成多套业务系统开发，掌握接口编写、SQL 优化与 Linux 基础部署，
具备独立排错与前后端联调能力。
```

```text
应届生，精通 HTML/CSS/JavaScript、Vue3，
熟练使用 Element 组件库，参与多个页面开发与交互优化，
了解前端工程化基础，能快速完成需求迭代。
```

```text
自动化专业应届生，自学 Java 及 Spring Boot 框架，
独立开发校园图书借阅系统并完成上线部署，
熟悉 RESTful API 设计与 MySQL 数据库优化。
```

:::note
非科班转行的同学，弱化专业背景，强调"身份+技术栈"。面试官更关心你能做什么，而不是你从哪里来。
:::

## 五、专业技能——双线并行

这是整份简历变化最大的板块。2026 年的技能列表需要**传统技术 + AI 技术双线并行**。

### 传统技术线

| 分类 | 内容 | 熟练度 |
|------|------|--------|
| 编程语言 | Java 8/11、JavaScript、SQL | 熟练掌握 / 常用 / 了解 |
| 开发框架 | Spring Boot 2.x、MyBatis、Vue3 | 熟练掌握 / 常用 |
| 数据库 | MySQL、Redis | 熟练 / 掌握 |
| 工具环境 | Git、Docker、Maven、Linux | 熟练 / 掌握 |

**标注版本号**。写 `Spring Boot 2.x` 比写 `Spring Boot` 更严谨，面试官经常追问版本差异，提前写明也匹配 JD 关键词。

**扩展能力——监控告警与 SEO/GEO**。越来越多公司要求后端开发也得懂线上排查、会搭监控。如果你的简历上有 Prometheus、Grafana 这些关键词，面试官会觉得你是一个有全局意识的人。SEO（搜索引擎优化）和 GEO（生成式引擎优化）则是"写代码之后"的能力——项目做完了，怎么让用户看到？怎么让 AI 推荐你的产品？这些能力正在成为新的加分项。

### AI 技术线（新增核心板块）

这是 2026 年简历和新前几年简历最大的区别。

| 层级 | 能力 | 具体内容 |
|------|------|----------|
| 第一层 | AI 开发框架 | Spring AI、LangChain4j、RAG 检索增强生成、MCP 协议、Agent 智能体 |
| 第二层 | AI 应用实战 | 知识库构建、Prompt 优化、AI 产品功能设计 |
| 第三层 | AI 编程工具 | Cursor、Claude Code、GitHub Copilot——还能开发 MCP Server、Agent Skills 扩展工具能力 |
| 第四层 | AI 编程模式 | Vibe Coding（当下最流行的 AI 编程范式）、SDD（规范驱动开发）、Harness Engineering（系统化 AI 工程实践） |

```text
AI 开发框架
- Spring AI（熟练）：RAG 检索增强生成、MCP 协议集成、Agent 智能体编排
- LangChain4j（掌握）：文档分割策略、向量检索、Prompt Template 设计

AI 编程工具
- Cursor / Claude Code（熟练）：日常开发主力工具
- 具备开发 MCP Server、Agent Skill 扩展能力

AI 编程模式
- Vibe Coding、SDD、Harness Engineering
```

:::important
如果你担心"写了 AI 技能面试官会不会觉得太超前"——恰恰相反，如果今年你的简历上还没有 AI 相关关键词，那才可怕。招聘方看到一份全是传统技术的简历，第一反应可能是"这个人是不是对新技术不敏感"。

当然，不是让你硬编，而是先去学、去实践，然后自然写到简历上。
:::

## 六、实习经历

倒序排列，每条 3-4 点。

**格式：`岗位 | 公司名称 | 起止时间`**

开头一行建议写清楚你负责的产品和数据规模——日活多少、注册用户多少、PV 多少，选最能体现体量的一个就够了。面试官需要判断这个项目是不是真实的、是什么级别的体量。

**写法公式：技术动词开头 + 工作内容 + 落地效果/数据**

统一用技术动词：开发、编写、联调、修复、优化、部署、设计

```text
Java 后端开发实习生 | XX 科技有限公司 | 2025-07 ~ 2025-09
产品日活 5000+，注册用户 3 万+，日均 PV 10 万+

- 负责用户权限与订单模块 8 个核心接口开发，设计 6 张数据表，
  采用策略模式+工厂模式解决多渠道支付适配问题
- 针对列表查询进行分页与索引优化，解决全表扫描问题，
  接口响应时间从 1.2s 降至 300ms，提升 75%
- 配合前端完成接口联调，修复 Bug 20+ 个，
  参与基于 Spring AI 的智能客服功能开发，实现 RAG 知识库问答
- 在云服务器完成项目部署与基础运维，
  搭建 Prometheus + Grafana 监控面板，实现服务健康状态实时告警
```

:::caution
不要写"参与了 XX 项目""协助完成日常开发任务"这种笼统表述。面试官想知道的是**你具体做了什么模块、用了什么技术、解决了什么问题、带来了什么效果**。三条经历最好分别体现：架构设计能力、技术落地能力、运维与问题解决能力。
:::

## 七、项目经验

项目经验是简历的核心重点，也是面试时被问得最多的部分。

**格式：`项目名称 | 周期 | 角色 | 核心技术栈`**

**四段内容：项目用途 → 个人负责模块 → 技术难点&解决方案 → 量化成果**

多人项目必须写明自身分工，不写笼统的"参与项目开发"。

### AI 时代的项目搭配策略

建议准备两个项目，形成互补：

| 维度 | 项目 A：传统+AI 结合 | 项目 B：AI Native 项目 |
|------|----------------------|----------------------|
| 侧重点 | 后端基本功 + AI 应用深度 | AI 编程效率 + 快速交付能力 |
| 技术栈 | Spring Boot + MySQL + Spring AI | Cursor + Claude Code + 任意框架 |
| 量化成果 | 准确率提升 45%，成本降低 60% | 90%+ 代码由 AI 生成，3 天完成开发上线 |

**项目 A 示例：**

```text
AI 智能客服系统 | 2026-01 ~ 2026-03 | 后端开发 | Spring Boot + Spring AI + MySQL
项目地址：https://xxx.com | GitHub：https://github.com/xxx/ai-chat

- 负责知识库管理、RAG 检索、对话记录模块开发，
  基于 Spring AI 实现文档解析、Chunk 分割与向量检索
- 针对多轮对话场景设计上下文管理策略，
  通过 Prompt 优化与检索策略调整，问答准确率从 72% 提升至 95%
- 对接多家大模型 API，实现模型热切换与失败自动降级，
  单次对话成本降低约 60%
```

**项目 B 示例：**

```text
AI 热点资讯监控工具 | 2026-04 ~ 2026-04 | 独立开发 | Vue3 + Python + Claude Code
项目地址：https://xxx.com | GitHub：https://github.com/xxx/hot-monitor

- 项目中 90% 以上代码由 AI 生成，涵盖需求分析、技术选型、前后端开发全流程
- 设计多层信息过滤策略（来源筛选 + 关键词匹配 + 热度排序），
  每日自动聚合 50+ 信息源，去重准确率达 98%
- 独立完成方案设计、编码实现、上线部署全流程，
  从项目启动到上线仅用 3 天
```

:::note
有些同学担心写"代码由 AI 生成"会不会减分。2026 年的答案是：不仅不减分，反而加分。能高效利用 AI 编程工具本身就是一种能力。关键在于全局把控——需求分析、方案设计、技术选型、测试验证、上线部署——这些环节都是你在主导，AI 只是帮你加速了执行。

当然，前提是你真的参与了全流程决策，而不是把需求扔给 AI 就撒手不管。
:::

### 量化数据的兜底方案

准则要求量化结果，但有些项目确实拿不出"提升 40%"这类数据。如果强行编造反而危险——面试官追问测试方法时很容易穿帮。

没有性能数据，就用工作量或规模代替：

```
- 开发 6 个核心接口，设计 4 张数据表
- 经 30+ 条测试用例验证，核心功能全部通过
- 项目在云服务器稳定运行至今，累计处理请求 5000+
```

这同样是有效的量化——它证明了项目的真实性和你的工作体量。

## 八、技术技能速览

分类罗列，每项标注版本号和熟练度。

```text
技术技能
- 编程语言：Java 8（熟练掌握）、JavaScript（掌握）、SQL（熟练掌握）
- 开发框架：Spring Boot 2.x（熟练）、MyBatis（熟练）、Vue3（掌握）
- 数据库：MySQL（熟练）、Redis（掌握）
- AI 技术：Spring AI（熟练）、LangChain4j（掌握）、RAG（掌握）、MCP（了解）
- 工具环境：Git、Docker、Maven、Linux 基础操作（熟练）
- 扩展能力：Prometheus + Grafana 监控（掌握）、SEO / GEO（了解）
```

版本标注有两个作用：一是匹配 JD 关键词，二是应对面试追问。写"Spring Boot 2.x 熟练"既能通过关键词筛选，面试官追问 Spring Boot 2.x 和 3.x 的区别时你也有话可说。"熟练"建议替换为更克制的"熟练掌握/常用"，避免被挑刺。

不写 Office 等基础软件。

## 九、附加补充（可选模块）

没有以下内容就直接删掉整块，不要硬凑：

- 开源项目/代码仓库亮点
- 技术博客、持续输出文章
- 算法刷题（LeetCode 150+，熟悉常见算法与解题思路）
- 程序设计竞赛奖项
- 技术证书（软考、红帽、AWS 认证等）

```text
技术补充
- 刷题平台：LeetCode 刷题 150+，熟悉常见算法与数据结构
- 竞赛：校级程序设计竞赛二等奖
- 博客：持续输出技术文章 10+ 篇，累计阅读量 5 万+
- 证书：软考中级——软件设计师
```

## 十、排版与格式规范

排版决定了面试官阅读简历的第一感受。统一规范能大幅提升简历的专业感。

| 项目 | 规范 |
|------|------|
| 字体 | 中文微软雅黑/黑体，英文 Arial |
| 字号 | 姓名 18-20 号，模块标题 14-16 号，正文 10-12 号 |
| 布局 | 纯单栏，无边框、表格、图标、图片、二维码、证件照 |
| 日期格式 | 统一 `YYYY-MM ~ YYYY-MM` |
| 导出方式 | Word 另存为文本型 PDF，嵌入字体 |
| 文件大小 | < 2MB |
| 文件命名 | `王XX-Java实习生-25届-可实习6个月.pdf` |

:::warning
不要使用 PDF 编辑器直接画线、拖文本框，否则文字提取时会乱序。ATS 系统读到的可能是 "Jav aS pring Boot" 这样的碎片文本。

重要关键词（如 Spring Boot、MySQL、AI）在正文中至少出现两次，提升解析匹配度。

文件命名建议带上届次和实习时长，帮助 HR 在文件夹里一眼判断你的届次和到岗可能。
:::

## 十一、投递前自查清单

投递前逐项检查，避免因为低级错误被刷：

- [ ] 全篇无"性格开朗、学习能力强、团队合作"等主观套话
- [ ] 所有经历、项目都有具体技术 + 简单量化结果
- [ ] 重要关键词（Spring Boot、MySQL、AI 等）在正文中至少出现两次
- [ ] GitHub/个人网站链接可正常访问
- [ ] 技术名词拼写无误（Java 不是 Javascript，Spring 不是 Sprint）
- [ ] 整体内容控制在 1 页内
- [ ] 复制内容到记事本，文字无错乱、无丢失
- [ ] 求职意向与投递岗位匹配，不要"一份简历投所有公司"
- [ ] AI 相关技能真实可靠，能经得起面试追问
- [ ] PDF 为文本型（非扫描型/图片型），可直接选中文字复制

:::caution
第九条值得多说一句。面试官如果发现你写了 AI 技能却一问三不知，那不仅 AI 能力的印象分归零，整个简历的可信度都会打折扣。不会的技能可以不写，简历诚实比好看更重要。
:::

---

*简历不是一次性作品，而是持续迭代的产品。每学一项新技术、每完成一个项目，你都应该同步更新简历。建议每隔一个学期重新审视一次——那时候的你和现在，一定不一样。*
