## 一、Codex 是谁：OpenAI 的桌面 Agent 答卷

如果你看过「[编程生涯：Claude Code](../编程生涯claude-code/)」和「[编程生涯：Hermes Agent](../编程生涯hermes-agent/)」，会发现这两篇的核心都在讲「终端里的 Agent」——一款在黑白命令行里打字交互，另一款用 YAML 和 CLI 配置一切。它们很强，但都有同一个门槛：**你得不怕终端**。

Codex 不一样。它是 OpenAI 推出的桌面端 AI Agent 程序，有完整的图形界面、可视化的权限管理、拖拽式的文件操作，甚至内置了一个能预览网页和批注修改的浏览器。

用一个类比来解释三者的定位差异：

| <br />    | Claude Code | Hermes Agent     | Codex                 |
| --------- | ----------- | ---------------- | --------------------- |
| **形态**    | 终端 CLI      | 终端 CLI + Desktop | 桌面 App + Web + Mobile |
| **目标用户**  | 专业开发者，不怕终端  | 自部署团队，需要开源       | 零基础办公 + 开发者           |
| **背后的公司** | Anthropic   | Nous Research    | OpenAI                |
| **核心优势**  | 上下文工程，源码级设计 | 自进化，多平台 Gateway  | 桌面 GUI，Computer Use   |
| **模型绑定**  | 可切换任意模型     | 20+ 提供商          | 仅 OpenAI GPT          |

简单说就是：**Claude Code 是工程上的天花板，Hermes Agent 是开源界的六边形战士，而 Codex 是普通用户最容易上手的那个。**

:::warning
一个必须提前知道的限制：Codex 目前**只支持 OpenAI 的 GPT 模型**，不能像 Claude Code 那样切换到国产模型或开源模型。这意味着你的使用成本完全取决于 OpenAI 的定价策略。如果你计划长期依赖 Agent 编程，建议不要把鸡蛋放在一个篮子里——Codex 做日常操作，留一条「换模型」的后路。
:::

### 1.1 装起来看看

下载安装没什么门槛——去官网下载对应操作系统的安装包，用 ChatGPT 账号登录就行。免费账号也能用，但额度有限，建议 Plus 会员（每月 20 刀，大约 150 元），额度对日常使用来说很充裕。

首次打开会问你「希望 Codex 处理什么工作」——选编程或日常工作，Codex 会根据选择预装插件和 Skills。然后点一下初始化沙盒（Sandbox），就进入主界面了。

Codex 的界面是经典的三栏布局：

```text
┌─────────────────┬──────────────────┬────────────────┐
│   左侧任务列表    │    中间对话窗口    │  右侧多功能区域   │
│                 │                  │                │
│  ├─ 项目 A       │  你：帮我写一个    │  文件预览       │
│  │  └─ 任务 1    │  博客系统         │  浏览器         │
│  ├─ 项目 B       │  Codex：好的，    │  Git 改动       │
│  │  └─ 任务 2    │  我先规划一下…     │  终端          │
│  └─ 对话归档      │                  │                │
└─────────────────┴──────────────────┴────────────────┘
```

跟 Claude Code 那种全终端操作的第一印象完全不同——Codex 更像一个 IDE 和聊天工具的混合体，上手几乎零门槛。

### 1.2 额度与模型

Codex 的额度有两层限制：**五小时限额**和**周限额**，任意一个用完都需要等重置。在设置里可以查看剩余比例。

模型方面，目前主推 GPT-5.5，也支持切换到 GPT-5.4 等。可以调节四个思考强度（low / medium / high / extra high）和两种速度模式（standard / fast）。快速模式下推理速度提升 50%，但消耗双倍额度——赶工时用，平时省着点。

上下文管理有个很直观的设计：对话输入框旁边有一个小圆圈，显示当前上下文占用比例。鼠标悬停能看到更详细的占用明细。当上下文接近满时，Codex 会自动压缩历史；你也可以手动输入 `/compress` 主动触发压缩。

:::note
AI 圈有一个通用经验：**清空好于压缩**。当一个任务告一段落后，开一个新对话比在旧对话里压缩更有助于 AI 集中注意力。尤其当前后两个任务毫无关联时，开新对话几乎是必须的。
:::

## 二、沙箱权限：Agent 的安全边界工程

如果说 Claude Code 最核心的工程亮点是上下文压缩和分层记忆，那 Codex 最值得拆解的工程设计就是它的**沙箱权限系统**。

### 2.1 什么是沙箱

**沙箱（Sandbox）** 是 Codex 权限系统运行的地基。当你选择一个本地文件夹作为「项目」时，这个文件夹就变成了沙箱——Codex 可以在里面自由读写文件，但不能触碰沙箱外的内容。

关键在于：**这不是靠模型自觉遵守的，而是操作系统级别的强制约束。** Mac 上用的是系统内置的 Seatbelt 沙箱机制，Windows 上也有等价的底层实现。这意味着就算大模型「抽风」想删除 C 盘的系统文件，操作系统也会直接拦住。

```text
用户电脑
┌──────────────────────────────────────────┐
│                                          │
│  ┌──────────── 沙箱（项目文件夹）─────────┐ │
│  │                                     │ │
│  │  Codex 可以自由读写这里的所有文件       │ │
│  │  可以在这里执行终端命令                 │  │
│  │                                     │  │
│  └─────────────────────────────────────┘  │
│                                           │
│  ❌ 沙箱外文件：不可读、不可写、不可删         │
│  ❌ 默认禁止联网（需提权）                   │
│                                          │
└──────────────────────────────────────────┘
```

### 2.2 两种默认限制

沙箱之外，Codex 还有两个硬性限制：

1. **不能修改沙箱外的文件**——删 D 盘这种事，在沙箱体系下根本不会发生
2. **默认禁止联网**——AI 没法自己偷偷去查外部信息

如果 Codex 确实需要越权操作（比如安装 Node.js 需要联网下载），它会发起**提权请求（Escalate）**，询问你是否允许。你可以选择「仅本次允许」或「以后都允许」。

### 2.3 三种权限档位

Codex 提供了三个档位，从左到右安全递降、便利递升：

| 档位           | 行为                               | 典型场景               |
| ------------ | -------------------------------- | ------------------ |
| **默认权限**     | 沙箱内自由操作，越权必须人工审批                 | 新手刚上手，或操作敏感项目的场景   |
| **自动审查**（推荐） | 小模型自动对提权操作做安全分级，低风险直接放行，高风险才触发人工 | 日常高效使用，平衡安全与效率     |
| **完全访问**     | 无视所有限制，Codex 可以在电脑上做任何事          | 信任场景，或你已经摸透了它的行为模式 |

我个人的建议：日常用**自动审查**就够了。AI 会自动判断「去 npm 官网下个包」是安全的、「执行 rm -rf」是有风险的——前者直接放行，后者拦住问你。比默认模式省心，又比完全访问安心。

### 2.4 与 Claude Code 的权限对比

Claude Code 也有类似的三模式，但它们的实现哲学完全不同：

| <br />   | Codex              | Claude Code                      |
| -------- | ------------------ | -------------------------------- |
| **底层机制** | OS 级沙箱强制（操作系统的硬限制） | 模型自觉 + 参数开关（靠 AI 不犯错）            |
| **默认行为** | 沙箱内自由操作，越权需人工审批    | 每次写文件都要问                         |
| **自动模式** | 小模型做安全分级，低风险自动放行   | 自动编辑文件，但执行命令仍要询问                 |
| **极限模式** | 完全访问——系统级放飞        | `--dangerously-skip-permissions` |
| **安全兜底** | 即使完全访问，OS 底层仍有限制   | YOLO 模式下仍有影子分类器兜底                |

两者在「自动审查 / 自动编辑」这个档位上殊途同归——都是找一个安全与效率的平衡点。但 Codex 的 OS 级沙箱从根上更严格，Claude Code 的 YOLO 模式下的影子审查则更「信任但有检查」。

用「[编程生涯：Agent 原理及其开发框架全览](../编程生涯agent原理及其开发框架全览/)」里的话来说，这就是 **Harness Engineering** 的两种不同风格——Codex 用「马厩锁死」的方式约束 Agent，Claude Code 用「缰绳加哨兵」的方式管控 Agent。没有绝对的好坏，只有场景的不同。

## 三、本地文件与终端：Agent 的两只「手」

沙箱决定了能干什么，而文件和终端决定了「怎么干」。这一节是 Codex 最基础的实操——也是它跟传统 ChatGPT 最本质的区别。

### 3.1 项目工作区机制

传统 ChatGPT 要让 AI 看到你的文件，只有两种方式：把内容复制粘贴到对话框里，或者把文件上传上去（有格式和数量限制）。

Codex 不一样。它可以直接读写本地的任何文件——不限数量、不限格式。你只需要把一个文件夹设为「项目」，里面的所有文件就成了 AI 随时可以获取的上下文。

这种能力在日常工作中的体现很直观：

- **批量重命名**——80 个视频素材，文件名全是默认的乱码。我告诉 Codex「按内容自动重命名」，它先用抽帧技术提取每个视频的关键画面，然后一组一组识别内容，最后按「序号\_场景\_行动」的格式全部重命名完成
- **空间清理**——让 Codex 扫描「下载」文件夹，按照文件大小和使用频率给出清理建议，直接删除没用的预览文件
- **跨对话共享上下文**——同一个项目下可以开多个对话，每个对话的上下文独立，但它们都能访问同一个文件夹里的文件

### 3.2 终端命令执行

如果说文件操作让 Agent 能「看」到你的电脑，那终端命令让它能「动」你的电脑。

在授权后，Codex 可以执行终端命令——安装依赖、克隆仓库、部署项目，全都是它自己来。

举个例子，安装 Node.js：

```bash
帮我安装 Node.js
```

就这么一句话。Codex 会自动去官网下载安装包、执行安装流程、验证安装结果。整个过程在自动审查模式下甚至不需要你点确认，因为这是 AI 判断为「低风险操作」的典型场景。

更有意思的是一键安装其他 Agent。比如让 Codex 安装 Hermes：

```text
最近有个叫 Hermes Agent 的框架很火，帮我安装一下
```

Codex 会自己去搜索 Hermes 的官方文档，找到安装命令，执行安装，然后验证是否装好——全程不需要你手动干预。装完之后它还会告诉你「已经装好了，接下来可以这样启动…」。

:::tip
我在「[编程生涯：Hermes Agent](../编程生涯hermes-agent/)」里详细拆解了 Hermes 的五大核心能力。如果你先让 Codex 装好了 Hermes，再去看那篇文章跟着实战，两边一起学效率翻倍。
:::

### 3.3 并行任务管理

这是 Codex 很容易被忽略但非常实用的设计——**并行对话**。

你可以同时开多个对话，每个对话处理一个独立任务。左侧边栏会通过图标状态告诉你每个对话的进度：

- **转圈**：AI 正在工作中
- **绿色标签**：等待你批准某个提权操作
- **蓝色圆点**：任务已完成

这种设计让你可以在 Codex 帮 A 项目写代码的同时，让 B 项目的依赖安装悄悄在后台跑完——相当于同时指挥好几个 AI 员工，互不干扰。

## 四、记忆系统：让 Agent 越用越懂你

你每次开一个新对话，Codex 对你来说就是一个「从零开始」的 AI。它不记得你叫什么、项目用什么技术栈、你有哪些编码偏好。这就像每天早上醒来都失忆一次——你跟它聊过的每一件事都要从头交代。

记忆系统就是为了解决这个问题。

### 4.1 全局记忆：agents.md

在设置 → 个性化 → 自定义指令里写的内容，就是全局 agents.md。它对这台电脑上**所有项目、所有对话**都生效。

适合在这里写一些通用的工作习惯：

```markdown
- 回复用中文，代码注释用英文
- 修改文档使用紫色文字 + 删除线方式，不要直接修改原内容
- 禁止使用脚本批量删除文件或目录
- 代码中优先使用双引号
- 不做超出项目范围的操作
```

:::important
全局 agents.md 是 Codex 的安全底线。我在里面加的最重要的一条就是「禁止批量删除」——有用户反馈过 AI 误删数据的案例，一条规则堵住了这条路。这个思路跟 Claude Code 的「默认拒绝策略」异曲同工。
:::

### 4.2 项目级记忆

在项目根目录创建 `agents.md` 文件，只对当前项目生效。Codex 每次新对话都会自动读取这个文件的内容。

你在里面可以写：

```markdown
# 项目概览

- 技术栈：React + TypeScript + Vite
- 后端：Node.js + Express
- 数据库：PostgreSQL

# 编码规范

- 组件使用函数式 + TypeScript
- CSS 使用 Tailwind
- API 请求统一通过 src/api/ 目录

# 注意事项

- 修改数据库配置前必须询问
- 敏感信息使用环境变量
```

两种创建方式：你可以自己手写，也可以让 Codex 通读整个项目后自动生成。后者更方便——当项目有一定规模后，让 AI 自己理解项目结构、技术栈、文件组织方式，然后产出一份 agents.md。

```text
请通读当前项目的所有文件，然后把学到的项目知识保存到 agents.md 里
```

### 4.3 自动记忆

在设置里开启「启用记忆」后，Codex 会在对话空闲时自动总结有用的信息，存为记忆文件。后续遇到相关场景时会自动召回。

不过自动记忆有几个限制：

- **太短的对话不记**——至少需要一些有意义的对话才能触发
- **额度太低时不记**——记忆生成本身也会消耗额度
- **不建议手动修改**——自动记忆文件格式比较特殊， OpenAI 官方推荐只需删减没必要的信息

### 4.4 与 Claude Code / Hermes Agent 的记忆对比

这三套记忆系统体现了不同的工程哲学：

| <br />   | Codex               | Claude Code              | Hermes Agent         |
| -------- | ------------------- | ------------------------ | -------------------- |
| **全局层**  | 全局 agents.md（个性化设置） | `~/.claude/CLAUDE.md`    | SOUL.md + 全局 config  |
| **项目层**  | 项目根目录 agents.md     | 项目根目录 CLAUDE.md          | 每个 Profile 独立配置      |
| **自动层**  | 自动记忆（AI 空闲时总结）      | Auto Memory（后台索引 + 按需加载） | Memory + Session 数据库 |
| **存储形式** | 文本文件                | 索引 + 话题文件 + 历史对话         | SQLite + Markdown 文件 |
| **核心哲学** | 「立规矩」——你告诉 AI 该怎么做  | 「目录 + 按需加载」——效率优先        | 「自进化」——越用越懂你         |

三者的共同点是都遵循\*\*「分层存储、索引优先」\*\*的原则——不把全部记忆塞进上下文，而是在需要时才加载。区别在于各自对「自动」和「人工」的取舍不同。

## 五、Fork 与会话管理：Agent 操作的时间机器

你让 Codex 改了一版代码，改完发现不如不改——这个场景是不是很熟悉？

Codex 的处理方式很特别：它不能直接「回滚」代码，但它提供了一个叫 **Fork（分叉）** 的设计，配合 Git 可以实现「对话 + 代码」双重回滚。

### 5.1 Fork：复制会话，不复制代码

Fork 的本质是：**在某个消息位置复制一个对话分支**。后面的消息全部丢弃，从分支点开始新对话。

```text
原始对话：
  你说："帮我做个番茄钟"
    ↓
  Codex：好的，创建一个网页…
    ↓
  你说："改成蓝色主题"      ← 在这里 Fork
    ↓
  Codex：改成蓝色了…
    ↓
  你说："算了，还是紫色吧"

Fork 后的新对话：
  你说："帮我做个番茄钟"
    ↓
  Codex：好的，创建一个网页…
    ↓
  （从这里继续新的对话）
```

Fork 只复制对话内容，不会自动回滚代码。要同时回滚代码，需要配合 Git：

1. 用 Fork 复制对话（丢弃后续的对话历史）
2. 用 Git 回滚代码到 Fork 之前的提交
3. 在新 Fork 的对话里继续

### 5.2 Fork into Local vs Fork into New Worktree

Codex 提供了两种 Fork 方式：

| 方式                         | 代码位置       | 适用场景            |
| -------------------------- | ---------- | --------------- |
| **Fork into Local**        | 继续使用当前项目目录 | 小改动，修改完直接覆盖     |
| **Fork into New Worktree** | 创建独立的新目录   | 大改动，需要在独立空间并行开发 |

Fork into New Worktree 背后用的是 Git Worktree 机制——它不是把代码再复制一份，而是基于同一个 Git 仓库创建了一个新的工作目录。两个目录下的修改互不干扰，最后可以合并回主干。

这种设计在「同时进行多个实验性改动」时特别有用。比如你让 Codex 同时尝试两种不同的 UI 方案，每个方案开一个 Worktree，互不影响，哪个效果好就留哪个。

## 六、计划模式与项目开发

前面讲的都是 Codex 的「基础能力」——会读文件、会执行命令、会记住东西。但 Agent 真正区别于普通 AI 聊天工具的，是**它能在复杂任务中自主规划并执行**。

### 6.1 Plan Mode：先出方案，再动手

开启计划模式（Plan Mode）后，Codex 不会直接干活，而是先出一份完整的项目方案，跟你确认后再动手。

这个模式尤其适合两类场景：

1. **任务本身很复杂**——架构迁移、新功能开发、大型重构，需要全局规划
2. **你自己也没想清楚**——Codex 会用问题卡片的方式主动问细节，帮你理清需求

举个实战例子。我用 Codex 做个人主页时，开启了 Plan Mode 并输入需求：

```text
我想做一个个人品牌网站，展示我的作品和履历
```

Codex 没有直接写代码，而是先问我一系列问题：

- 想要什么风格？（极简 / 科技感 / 个人品牌）
- 需要哪些页面？（首页 / 作品集 / 关于我 / 联系方式）
- 要不要多语言？（中英双语还是仅中文）
- 要不要博客功能？（后期是否需要发布文章）

这些问题以卡片形式弹出，我逐个选择。确认完所有细节后，Codex 产出一份完整的实现计划——包含技术选型、页面结构、路由设计、部署方案。我确认后它才开始写代码。

### 6.2 Image2 生图：内置的设计师

开发个人主页时还需要配图。Codex 内置了 OpenAI 最新的 Image2 生图模型，可以直接在项目中生成配图。

实际流程是这样的：

1. 告诉 Codex 需求：「在个人主页上生成几张高级感的配图」
2. Codex 调用 Image2 生成多张风格一致的插图
3. 自动把图片嵌入网页，甚至做好适配和响应式
4. 不满意的地方可以直接在浏览器上批注修改

不需要打开别的设计软件，不需要到处找免费素材——**全部在 Codex 里完成**。

### 6.3 Steer：中途抢方向盘

AI 执行长任务时，你发现它走偏了——怎么办？

传统的做法是等它执行完当前步骤，然后告诉它「不对，重来」。但在 Codex 里，你可以随时使用 **Steer（引导）** 功能，在 AI 执行过程中插入修正指令。

具体操作：在 Codex 运行过程中，点击「引导」按钮（或按快捷键 Ctrl + Enter），输入修正指令。Codex 不会打断当前正在执行的操作，而是在下一次调用工具时带上你的新指令。

这就好比你派了一个人去办事，发现他走错了路——不用等他走到终点再回头，而是直接给他导航纠正路线。

### 6.4 内置浏览器与 Annotate 批注

Codex 内置了一个浏览器，可以在右侧面板预览开发中的网页。更重要的是，它支持**批注（Annotate）** 功能：

1. 在预览页面点击「批注」按钮
2. 直接选中页面上需要修改的元素
3. 写下修改意见（比如「把这个 Logo 放大一点」「把这张图换成暖色调」）
4. 提交后 Codex 自动定位到对应代码并修改

这个设计的巧妙之处在于：**你不是用「语言描述 Bug」，而是直接「指着屏幕说这里有问题」**。对于不太懂编程的人来说，这比「找到 CSS 文件里第 50 行的 padding 改成 20px」友好得多。

### 6.5 Git 集成与版本管理

Codex 底层用 Git 来管理代码变更。你可以：

- 让 Codex 初始化 Git 仓库，创建一个 `.gitignore` 排除不需要的文件
- 每次改完代码后自动或手动提交
- 通过右侧面板查看每次改动的文件差异（新增了什么、删除了什么）
- 不满意的地方可以逐块撤销（不是整个文件，而是单个代码块的维度）

Git Worktree 的集成更是让并行开发变得丝滑——开两个对话，在两个独立目录里各自干活，互不干扰，最后合并。

## 七、插件、Skill 与 MCP：无限扩展

Codex 的核心能力很强，但让它真正「万能」的是它的扩展生态。

### 7.1 Plugin 的内部结构

Codex 的插件市场里有大量官方和社区贡献的插件。每个 Plugin 通常包含三个组成部分：

```text
一个 Plugin =
  ├── App（工具集）：让 Codex 能调用外部服务
  │   以 Gmail 插件为例，App 提供了 24 个 action：
  │   - 发送邮件、归档邮件、打标签…
  │   - 每个 action 都是一个可以被 AI 调用的工具
  │
  └── Skills（说明文档）：告诉 AI 怎么用好这些工具
       ├── gmail-skill：怎么写邮件、怎么总结收件箱
       └── inbox-triage：怎么给邮件分类、哪些是紧急的
```

安装一个 Plugin，就是同时安装了对应的 App 和 Skills。AI 在执行任务时会自动去找匹配的 Plugin，不需要你每次都手动指定。

### 7.2 Browser Use：操控浏览器

Browser Use 让 Codex 可以操控浏览器——自动点击、填表单、翻页、抓取数据。

有两种模式：

1. **内置浏览器模式**——Codex 在后台打开一个无界面浏览器执行操作，不占用你的屏幕
2. **Chrome 扩展模式**——安装 Codex 的 Chrome 扩展后，AI 可以操控你已登录的 Chrome 浏览器，保留登录状态

第二个模式非常实用。比如你有一些需要登录才能访问的后台系统，Chrome 扩展模式让 AI 可以直接用你的登录态去操作，不需要额外配置 Cookie 或 Token。

### 7.3 Computer Use：操控整台电脑

这是 Codex 最「炸裂」的功能之一。Computer Use 让 Codex 可以用一个独立的虚拟鼠标，操控你的整个电脑——不只是浏览器，而是所有桌面应用。

实操一个场景看看：

```text
@computer
帮我打开音乐软件，放一首周杰伦的歌
```

Codex 会使用虚拟鼠标打开你的音乐 App，搜索歌曲，点击播放。与此同时，你还能继续用自己的鼠标做其他事情——因为那是两套独立的鼠标系统。

更实用的场景是批量操作：让 Codex 打开飞书、找到指定的文档、修改内容、再发送到群里。整个过程在后台执行，你不必盯着它做。

:::caution
Computer Use 目前有几个硬伤：1）仅支持 Mac；2）操作效率偏低，不适合高频交互；3）某些对自动化敏感的应用（如微信）可能会拦截 AI 的鼠标操作。能用终端命令和 Browser Use 解决的问题，优先用它们——Computer Use 是兜底方案。
:::

### 7.4 Skill 系统

Skill 是 Codex 里「沉淀工作流」的机制。一个 Skill 本质上是一个 `.md` 描述文件 + 配套脚本，告诉 AI 遇到某类任务时按照固定的流程来处理。

Skill 跟 Plugin 的区别在于：

- **Plugin** 侧重「连接外部服务」（连接 Gmail、连接 Netlify、连接 GitHub）
- **Skill** 侧重「固定操作流程」（先 A 再 B 再 C 怎么做）

**创建 Skill 的最佳实践：**

不要在一开始就试图设计一个完美的 Skill。先把任务流程手动跑通一遍——让 Codex 一步步完成你想要的输出。跑通后，用内置的 `Skill Creator` 告诉它「把刚才这一套流程做成 Skill」，它会自动生成 Skill 文件。

```text
# 跑通流程后
请把刚才写 GitHub 热门项目推荐文章的那一套流程，做成一个 Skill
```

创建成功后，以后在任何新对话中，输入斜杠加 Skill 名就能一键触发完整流程——不需要再重复写提示词。

### 7.5 MCP 协议

MCP（Model Context Protocol）是一个开放协议，它的目标是统一「大模型 ↔ 工具/数据源」的通信方式。

Codex 里配置 MCP 的入口在设置里的 MCP 服务器面板，但更推荐的方式是**直接把链接发给 Codex 让它帮你装**：

```text
帮我安装一个 Notion 的 MCP Server
这是链接：https://github.com/xxx/notion-mcp
```

Codex 会自己读取文档、安装依赖、帮你完成授权。

### 7.6 自动化定时任务

前面讲的都是「你发指令，AI 执行」的模式。定时任务让它变成了「AI 自己到点就干活」。

创建定时任务有两种方式：

**方式一：在自动化面板手动创建**
在左侧边栏的自动化面板点击新建，填写任务名称、触发时间、要执行的 prompt、使用的模型。

**方式二：让 Codex 帮你创建**
直接在对话里说：

```text
帮我创建一个定时任务，每周一早上九点运行「GitHub 热门项目推荐」这个 Skill，生成的图文发到飞书群里
```

Codex 会自动配置好所有参数。你可以在自动化面板里查看和修改触发时间、执行模型等设置。

:::tip
定时任务的「记忆」是逐渐积累的。每次执行完后，Codex 会把执行经验和结果写进一个 memory 文件——下次执行时，它知道上次哪些地方做得好、哪些需要优化。**定时任务跑得越久，输出质量越高。**
:::

## 八、手机端：出门在外也能遥控 AI

Codex 的手机端不是让你在手机上写代码，而是让你**用手机遥控电脑上的 Codex 干活**。

设置过程很简单：

1. 电脑端 Codex → 点击 Codex Mobile → 生成二维码
2. 手机上的 ChatGPT → 扫描二维码 → 建立连接

连接成功后，你在手机上发消息，电脑上的 Codex 就会执行。你可以：

- 让它操作日历删除一个日程
- 让它启动一个自动化任务
- 审批提权操作
- 查看运行进度和结果

这就等于你在地铁上、午休时、朋友聚会上，都可以随时让家里的电脑干活。Agent 从「随叫随到」进化成了「随时待命」。

## 九、三强横评：Codex vs Claude Code vs Hermes

| 维度       | Codex（OpenAI）                  | Claude Code（Anthropic） | Hermes Agent（Nous Research） |
| -------- | ------------------------------ | ---------------------- | --------------------------- |
| **产品形态** | 桌面 App + Web + Mobile          | 终端 CLI                 | 终端 CLI + Desktop（v0.16+）    |
| **目标用户** | 零基础办公 + 开发者                    | 专业开发者                  | 开发者 + 自部署团队                 |
| **权限机制** | OS 级沙箱强制                       | 模型自觉 + 参数开关            | YAML 配置                     |
| **记忆系统** | agents.md + 自动记忆               | CLAUDE.md 三层记忆         | Session + Memory + SOUL.md  |
| **扩展生态** | Plugin + Skill + MCP           | Skill + MCP + SubAgent | Skill + Plugin + MCP + Hook |
| **代码开放** | 闭源                             | 闭源（源码意外泄露）             | MIT 开源                      |
| **模型绑定** | 仅 OpenAI GPT                   | 可切换任意模型                | 20+ 提供商 400+ 模型             |
| **独特优势** | 桌面 GUI + Image2 + Computer Use | 源码级上下文工程               | 自进化 + 多平台 Gateway           |
| **价格**   | 20刀/月起（Plus）                   | API 计费 / 订阅            | 开源免费                        |
| **学习曲线** | 低                              | 中                      | 较高                          |

### 怎么选

如果你的情况是……：

- **编程小白 / 办公自动化**——不用犹豫，直接选 **Codex**。它的图形界面、Image2 生图、Computer Use 都面向非程序员设计
- **专业开发者 / 日常编程**——**Codex + Claude Code 搭档**。用 Claude Code 写代码（质量高），用 Codex 处理文件操作和部署（效率高）
- **需要自部署 / 多消息平台 / 开源偏好**——**Hermes Agent**。它的 25+ 消息平台 Gateway 和自进化能力在企业场景下很有价值
- **预算充足**——**三件套全上**。Codex 做桌面操作、Claude Code 做深度编程、Hermes Agent 做后台服务，各司其职

## 十、总结：从「问 AI」到「管 AI」

回顾 Codex 的全部能力，我最大的感触不是哪个功能多强，而是一个本质的转变：

**我们正在从「问 AI」的阶段，走向「管 AI」的阶段。**

过去用 ChatGPT：有问题 → 问一下 → 得到答案 → 走了。

现在用 Codex 这样的 Agent：给它上下文 → 指明目标 → 检查计划 → 监督过程 → 验收结果 → 沉淀为 Skill → 设成自动化。

你不再是一个「提问者」，而是一个「管理者」。Codex 是员工，你负责告诉它干什么、怎么干更好、把好的做法固定下来。

引用「[编程生涯：从古法编程到 SDD](../编程生涯从古法编程到sdd/)」里提到的编程范式演进——从手写每一行代码的古法编程，到用 AI IDE 的 SDD（规范驱动开发），再到用 Agent 的「管理式编程」。Codex 就是这最后一步的典型代表。
