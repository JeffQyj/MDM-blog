## 开篇承接：顺着业务流，回到「需求起点」

这一篇让我们沿着制造业数字化的主线继续：**需求（CRM）→ 定义（PLM）→ 计划（ERP）→ 执行（MOM）→ 贯通（系统集成）**。

制造业的整条链路，起点从来不在研发部，而在客户那里。一份销售订单签下来，PLM 的设计、ERP 的计划、MOM 的生产才会被依次点燃。而承接这张订单、记录需求、管理客户全过程的，就是 **CRM（Customer Relationship Management，客户关系管理）**。

## 一、岗位画像：CRM 运维工程师做什么

CRM 覆盖前端**营销—销售—交付—售后**全客户生命周期。CRM 运维工程师的核心职责，是让这个「客户旅程」上的每个环节都跑得顺。

### 1.1 客户全生命周期管理（2B & 2C）

CRM 运维首先要理解两类客户模式：

| 模式     | 全称                 | 对象      | 管理重点         |
| ------ | ------------------ | ------- | ------------ |
| **2B** | To Business，面向企业客户 | 经销商、分销商 | 信用额度、批量订单、账期 |
| **2C** | To Consumer，面向消费者  | 终端消费者   | 个体画像、复购、售后   |

在制造业，往往 2B 和 2C 并存——工厂既批发给经销商，也偶尔直营零售。两类客户的数据模型、流程设计完全不同，这是 CRM 运维的第一道分水岭。

### 1.2 客户旅程的完整闭环

```text
市场活动 → 线索 → 商机 → 报价(CPQ) → 合同/订单 → 发货 → 售后
```

每一段都有对应的模块：市场管理、线索管理、客户管理、下单管理（CPQ）、产品管理、发货申请、提货管理、售后管理、销售预测、客户费用与信用额度管理。

## 二、CPQ：「销售智能引擎」

**CPQ（Configure, Price, Quote，配置、定价、报价）** 是把「配置、定价、报价」合成一步的功能：销售选好产品属性，系统自动算出价格、生成报价单。在销售易里，它是 CRM 的原生模块，客户、商机、报价数据天然一体，销售全程在 CRM 里完成，不需要在系统间来回倒腾。

不过对制造业而言，CPQ 的难度远超互联网行业。互联网的 CPQ 是「下拉菜单选功能、查个价格表」；制造业的 CPQ 要做「产品配置 = 工程验证」级别的复杂度——选个钛合金壳体配哪种密封件、选个电机组合是否符合防爆认证，这些工程约束都要写进配置规则里，系统自动拦截不兼容的组合。

### 2.1 制造业 CPQ vs 通用 CPQ

| 维度         | 通用 CPQ     | 制造业 CPQ                                |
| ---------- | ---------- | -------------------------------------- |
| **配置**     | 下拉菜单选功能    | 200+ 属性（材料/尺寸/电机/涂层/认证）带 BOM 依赖与工程约束   |
| **定价**     | 静态价目表查找    | 多属性计算：材料成本 + 配置附加 + 客户合同 + 区域加价 + 阶梯折扣 |
| **审批**     | 线性：销售经理批折扣 | 条件分支：工程验证可行性、定价查利润、合规审受控产品             |
| **输出**     | 品牌化 PDF 报价 | 报价含技术规格、图纸、交期、BOM 明细、合规证书              |
| **ERP 连接** | 单向：报价推 CRM | 双向：拉物料成本/库存，推订单回 ERP 驱动生产              |

### 2.2 CPQ 解决了什么核心痛点

| 痛点   | CPQ 之前                  | CPQ 之后           |
| ---- | ----------------------- | ---------------- |
| 效率低  | 复杂报价需 5-7 个工作日（多部门反复沟通） | 压缩到分钟级，复杂配置数小时   |
| 易出错  | 人工计算错误率 15%-20%         | 固化规则后错误率降至 1% 以下 |
| 利润流失 | 约 23% 订单亏损源于人工报价错误      | 实时利润测算，报价即显示预估毛利 |
| 协同差  | 销售、技术、财务来回踢皮球           | 打通「报价到回款」全流程     |

:::note
行业数据：CPQ 可将销售周期平均缩短 28%，报价等待审批的时间减少最多 95%，报价生成效率提升 30%-50%。国内装备制造案例显示，应用 CPQ 后报价周期平均从 6 天缩短至 1.5 天。
:::

## 三、把 CPQ 用起来，CRM 运维要过的三关

CPQ 是原生模块，但原生不等于开箱即用。作为 CRM 运维，有三关要过：

| 关卡        | 运维要做什么                                              | 对应配置         |
| --------- | --------------------------------------------------- | ------------ |
| **① 产品关** | 把散落在工程师脑子里、邮件里及文档里的配置规则、BOM 结构、定价策略收拢进系统，整理成统一的产品目录 | 产品主数据、配置规则   |
| **② 流程关** | 把线下报价流程搬上线，设好自动化审批规则，打通与 ERP、PLM 的数据衔接              | 审批流、数据接口     |
| **③ 数据关** | 持续统计报价成功率，用历史数据反哺定价策略，让报价越报越准                       | 报表分析、AI 定价建议 |

## 四、销售漏斗、客户分层与信用额度

### 4.1 销售漏斗：把商机管成一条流水线

CRM 运维的核心场景之一，是**销售漏斗（Pipeline，销售管道）**——把「可能的生意」分成阶段，逐层过滤，直到成交：

```text
线索 → 初步沟通 → 方案报价(CPQ) → 商务谈判 → 赢单/输单
```

- 每一层都有「转化率」，漏斗太瘦说明线索质量差，中段塌陷说明报价或方案有问题；
- 销售预测的本质，就是「漏斗各阶段金额 × 历史转化率」的加权估算——这直接联动 ERP 的 MRP 和 MOM 的排产。

:::tip
漏斗的真正价值，在于**暴露问题**。某层转化率突然暴跌，一定是有环节出了岔子——是报价太慢？还是交期承诺太激进？**漏斗是销售部门的「体检报告」，也是 CRM 运维优化流程的依据。**
:::

### 4.2 客户分层：RFM 模型

不是所有客户都值得同样的投入。**RFM 模型**用三个维度给客户打分分层：

| 维度               | 含义       | 作用     |
| ---------------- | -------- | ------ |
| **R（Recency）**   | 最近一次消费时间 | 越近越活跃  |
| **F（Frequency）** | 消费频次     | 越频越忠诚  |
| **M（Monetary）**  | 消费金额     | 越高越有价值 |

将三档得分组合，可把客户分成高价值、成长型、唤醒型、流失型等群体——高价值客户给专属服务与信用额度，流失型客户触发挽回策略。

### 4.3 信用额度：制造业 2B 的「安全带」

在 2B 场景，客户往往是「先拿货、后付款」的赊销模式。**信用额度（Credit Limit）** 就是给客户设的一条账期红线：

- 超出额度，系统自动冻结新订单、拦截发货，除非走特批；
- 额度与应收账龄联动：欠款越久，可用额度越少；
- 这是「应收账款风险」的第一道闸——额度管不好，坏账就是利润的黑洞。

:::warning
信用额度的实施铁律：**额度必须在系统里强控，而不是靠业务员「心里有数」**。
:::

## 五、改单缓释策略：把「地震」变成「涟漪」

客户或计划员对已下达的销售订单（SO）或生产工单（MO）发起紧急修改（提前交期、缩减数量、更换 BOM 版本），这就是「改单」。改单的入口就在 CRM——客户提出变更，销售在 CRM 里发起「订单变更申请单」，这是整条改单链的源头。

改单不可避免，但作为 CRM 运维，你的目标是**用系统逻辑把「地震」变成「涟漪」**。针对改单，拆出四层核心缓释策略：

### 策略一：源头拦截——物理上不让乱改

改单请求在 CRM 里发起后，怎么批、批完往哪推，是 CRM 运维要设计的。核心是在订单状态上做**冻结**：「已下采购单」禁止改数量（防止对供应商违约），「已上线生产」禁止改 BOM（防止现场混料）。客户非要改，强制走「订单变更申请单」专项审批流——**让销售去面对客户、承担压力，而不是让系统无脑执行**。

### 策略二：物料层缓释——联动库存反查与 ATP 重算

客户把交期从 10 号提前到 5 号，最大伤害在物料。系统先执行 **ATP（Available To Promise，可承诺量）重算**：检查在途、在制、在库的料能否支撑新日期。缺料就弹「风险预警」，推荐「分批交付」（先交 50，剩 50 晚 3 天）。

同时，缩减数量的场景会自动触发「多余库存占位」——原来锁定的 100 个专用物料现在只做 80 个，系统不会释放那 20 个回公共池（防止被其他单抢走），而是转为「客户专属呆滞库存」，等客户下次下单优先抵扣。

### 策略三：产能层缓释——智能工单拆分与负荷再平衡

改单导致紧急插单，硬塞会搞瘫产线。MOM 收到改单指令后**不修改原工单**，而是执行「工单拆解」：原工单照常做，针对变更部分生成独立「追加/变更工单」并置顶最高优先级，耗时工序自动外协（转 **OEM，Original Equipment Manufacturer，原始设备制造商**）或分派给产能富余的兄弟工厂。

### 策略四：财务层缓释——自动计算改单成本并推送账单

系统配置「改单费率表」，改单发生时自动比对原计划与新计划的人、机、料、法差额，算出「改单附加费」作为订单行项目推给销售。**销售看到要给客户多收钱，自然会掂量值不值得逼工厂改**——这是通过系统规则倒逼前端提高预测准确率的最强手段。

:::tip
落地黄金法则：**改旧不如建新**——尽量不要直接覆盖原单据的日期和数量，原单作废（或冻结）、新单重建，保留数据痕迹方便月底复盘；并在流程中设「硬节点」——改单审批后必须等车间主任在 PDA 上点「确认接收变更」，下一道工序才解锁。否则系统自动推料，仓库不知道，照样送错旧料。
:::

## 六、能力要求总览：CRM 领域的成长矩阵

CRM 领域覆盖 9 个业务维度 + 1 个平台开发维度：

| 业务/技术维度          | 初级                  | 中级                     | 高级                                                      |
| ---------------- | ------------------- | ---------------------- | ------------------------------------------------------- |
| **市场管理**         | 掌握展会、推广、广告投放基础流程    | 管理市场活动，优化数据分析并通过 UAT   | 输出市场活动 **ROI（Return On Investment，投资回报率）** 优化方案，提升投放精准度 |
| **线索管理**         | 了解线索来源、分配规则及转化流程    | 搭建自动化线索分配与跟踪机制         | 输出线索转化优化方案，提升转化率                                        |
| **客户管理（2B&2C）**  | 了解经销商、终端消费者两类管理模式   | 开发客户分层与生命周期管理功能        | 提升客户留存率与价值贡献                                            |
| **下单管理（CPQ）**    | 了解配置、定价、报价全流程       | 优化 CPQ 逻辑，保障报价审批下单高效流转 | 输出 CPQ 逻辑优化方案，提升成交转化率                                   |
| **产品管理**         | 了解产品分类（款型、工艺、开向、图片） | 优化产品数据管理，支撑前端配置查询      | 输出产品信息管理优化方案，提升数据准确性                                    |
| **发货申请**         | 了解经销商、跟单员的发货申请流程    | 开发发货申请审批功能，通过 UAT      | 输出发货审批流程优化方案，提升单据处理效率                                   |
| **售后管理**         | 了解退换货、维修、投诉流程       | 开发售后管理功能，缩短服务响应        | 输出售后体系优化方案，提升客户满意度                                      |
| **销售预测**         | 了解历史数据、市场趋势、需求分析方法  | 搭建销售预测模型，提升准确性         | 输出预测体系优化方案，提升预测精度                                       |
| **客户费用&信用额度**    | 了解客户费用结算及信用额度管理规则   | 优化信用额度审批与结算管理流程        | 输出信用管理优化方案，降低企业信用风险                                     |
| **销售易 CRM 平台开发** | 了解平台基础功能与数据结构       | 开发内部流程、自动化规则及自定义组件     | 优化平台整体架构，提升可扩展性与稳定性                                     |

## 结语：沉淀「需求端」认知，走向「定义层」

CRM 运维工程师管的是一条完整的客户旅程：从线索到商机、从报价到订单、从发货到售后。贯穿其中的核心能力是三件事——**CPQ 让报价快而准，客户分层让资源用在刀刃上，改单缓释让突发变更不再掀翻整条链**。

如果要用一句话概括 CRM 运维的岗位本质，那就是：**把客户的「想要」变成系统里一张能被全链路执行的订单。** 销售在 CPQ 里选中的每一个配置项，往后会变成 PLM 的图纸、ERP 的采购计划、MOM 的生产工单——CRM 是这条链的第一把火，CRM 运维工程师的工作就是把火点得准、点得稳。
