## 开篇承接：五根手指，如何握成拳头

前五篇，我们认识了五个岗位：

- **实施工程师**：客户与代码之间的桥梁；
- **CRM 运维工程师**：客户需求的翻译官；
- **PLM 运维工程师**：主数据源头的守门人；
- **ERP 运维工程师**：资源与财务的调度中枢；
- **MOM 运维工程师**：车间执行层的大脑。

它们是五根手指，各有各的本事。但制造业数字化真正跑起来，靠的是它们**握成拳头**——而这，就是系统集成工程师的职责。这也是我日常工作的主战场：把华天 PLM、达索 Apriso、销售易 CRM、SAP B1 这几套系统，用接口、消息、ETL 串成一条流动的数据河。

## 一、岗位画像：隐形冠军

**系统集成工程师**，是企业信息孤岛的「翻译官」与「建筑师」。它负责将分散在不同业务系统中的数据、流程、功能打通，实现端到端的业务自动化和数据统一——让 ERP、CRM、PLM、MOM 这些异构系统**安全、可靠、高效地协同运转**。

为什么叫「隐形冠军」？因为它不像 MOM 运维那样站在车间聚光灯下，也不像 ERP 运维那样每天对着账本。它藏在系统与系统之间，**哪条数据流断了，它才出现；而它不在的时候，系统就一直在正常流动。**

## 二、基础设施工程师：所有系统的「地基」

在整条制造业数字化的能力版图里，有一个容易被忽略的维度——**IT 基础设施**。它不在业务主线上，却是所有系统的运行底座：数据中心、服务器、网络、云、安全，一个都不能少。

**基础设施工程师**，就是守住这片地基的人。它的工作横跨本地机房与云端两大战场，可以概括为三类：

- **本地侧**：机房与服务器、办公与工厂网络、打印机考勤机等 IT 外围设备；
- **云端侧**：阿里云 ECS/VPC、RDS 云数据库、混合云统一调度；
- **安全侧**：防火墙、**IDS（Intrusion Detection System，入侵检测系统）/ IPS（Intrusion Prevention System，入侵防御系统）**、VPN、访问控制与加密。

这 7 个维度，构成 IT 基础设施领域的完整能力矩阵：

| 业务/技术维度    | 初级                            | 中级                         | 高级                        |
| ---------- | ----------------------------- | -------------------------- | ------------------------- |
| 本地数据中心管理   | 了解机房、服务器、电源、冷却等基础设施           | 独立管理服务器、存储、网络设备，优化资源利用率    | 输出数据中心优化方案，提升能效、降低运维成本    |
| 办公与工厂网络管理  | 了解企业级网络架构，掌握 VLAN、交换机、防火墙基础配置 | 独立运维全场景网络，排查故障，优化流量管理      | 输出网络架构优化方案，提升稳定性、安全性，减少宕机 |
| IT 外围设备管理  | 了解计算机、打印机、考勤设备等 IT 资产管理流程     | 管理设备全生命周期，提供远程支持，优化运维效率    | 输出 IT 资产管理优化方案，提升硬件使用效率   |
| 阿里云服务器管理   | 了解 ECS、VPC、对象存储等基础云产品架构       | 独立管理云服务器，优化资源分配，保障高可用性     | 输出云架构优化方案，提升资源利用率、降低云成本   |
| RDS 云数据库管理 | 了解 MySQL、SQL Server 等云数据库基础运维 | 独立管理 RDS，优化数据库性能，保障数据安全    | 输出数据库优化方案，提升查询效率、降低宕机风险   |
| 混合云基础设施管理  | 了解混合云架构，掌握本地与云环境运维要点          | 统一管理本地与云端资源，优化 IT 资源配置     | 输出基础设施优化方案，提升运维自动化程度      |
| IT 安全管理    | 了解访问控制、加密、防火墙策略等安全基础概念        | 管理防火墙、VPN、IDS/IPS，优化企业安全策略 | 输出安全体系优化方案，提升入侵检测能力，保障合规  |

:::note
为什么在系统集成篇提它？因为**集成是让系统流动起来，基础设施是让系统活下去**。接口调不通，未必是代码问题，也可能是网络策略没放行——集成工程师排查问题，绕不开这层地基。它与「系统集成」一样，是制造业数字化里最容易被低估、却最不能出错的领域。
:::

## 三、五条跨系统核心业务流程：把六篇串成一条线

前面几章我们拆解了岗位、底座与能力，这一章把它们拼回成一条条真实跑起来的业务流。制造业数字化真正跑起来的形态，是五条横跨多个系统的核心业务流程。

### 3.1 新品研发上市：概念到量产（CRM → PLM → ERP → MOM）

一条全新产品从客户提出需求到批量生产，要闯五关：

```text
CRM 客户新品需求立项 → PLM 设计 EBOM、出图纸、编 MBOM 工艺
→ PLM 同步物料/BOM/工艺至 ERP、MOM
→ ERP 运行 MRP 生成样品采购、试制生产计划
→ MOM 执行样品工单、制程检验，输出试产报告
→ 试产验证通过 → PLM 冻结正式版本 → ERP 下达量产计划 → MOM 批量生产
```

:::tip
这条流程的命门在「试产验证」。PLM 只有在试产通过后才冻结正式版本，否则图纸一改，后面 MRP 算的料、MOM 排的产全部作废。
:::

### 3.2 标准订单交付：从订单到回款（CRM → ERP → MOM → ERP → CRM）

这是企业每天重复最多的流程，也是「订单到现金（Order to Cash）」主线的落地形态：

```text
CRM 录入标准产品销售订单 → ERP 接收订单，MRP 运算
→ 下达采购 PO + 生产计划 → 供应商送货，MOM 仓储 IQC 入库
→ MOM 创建工单，车间领料生产、工序报工、成品 OQC
→ 合格成品入库数据回传 ERP，ERP 创建销售发货单
→ MOM 执行成品发货出库 → 出库实绩同步 ERP 开票
→ 交付状态同步 CRM 给销售查看
```

### 3.3 工程变更 ECN：一次修改，三系统联动（PLM → ERP → MOM）

ECN 的完整细节在 PLM 篇已经讲透，这里只看它在集成层的「跨系统步调」：

```text
研发发起 ECN（替换物料/修改工艺/改版 BOM）
→ PLM 审核生效，同步新版数据至 ERP、MOM
→ ERP 冻结旧 BOM，重算 MRP，区分旧料库存消耗/退换
→ MOM 区分：未开工工单切新版、在制工单消耗旧料隔离管控
→ 新旧物料库存、损耗同步 ERP 做成本调整
```

### 3.4 采购来料协同与生产异常闭环（ERP ↔ MOM，MOM → ERP → CRM）

这两条在 ERP 篇已详述，这里用一句话点出它们的「跨系统本质」：

- **采购来料协同**：核心是「物权移交」——ERP 的 PO 是承诺，MOM 的 IQC 入库是验收，退货单回传才真正闭环；
- **生产异常闭环**：核心是「异常分级路由」——缺料找 ERP 查采购、批量不良找 PLM 查设计、交期延误找 CRM 告知客户。**异常不可怕，可怕的是异常在系统里没有归口。**

:::important
五条流程的底层，是系列首篇讲的那条主链路：**需求（CRM）→ 定义（PLM）→ 计划（ERP）→ 执行（MOM）→ 贯通（集成）**。集成工程师的工作，就是让这五条流程里的每一次数据交接都「自动、可靠、可追溯」——交接断在哪，问题就出在哪。
:::

## 四、成长路径三阶段

结合前面各篇的岗位画像与五条业务流，智造工程师的成长路径清晰可见：

| 阶段              | 目标               | 动作                                                                |
| --------------- | ---------------- | ----------------------------------------------------------------- |
| **单点突破（中级达标）**  | 独立负责一个模块的运维和二次开发 | 从 MOM 生产管理或 ERP 销售/采购入手，吃透业务流程与平台工具（Process Builder / SAP B1 SDK） |
| **连线成面（跨系统集成）** | 设计并实现两系统间的数据流转   | 做「PLM BOM 发布 → ERP 自动创建物料」「CRM 订单 → ERP 销售订单」接口，掌握 API/ETL/消息队列   |
| **全局架构（高级优化）**  | 发现瓶颈，用技术优化业务     | 关注 OEE、库存周转率、交付周期等业务指标，输出「用数据自动采集减少人工报工」这类方案                      |

## 五、系列全景回望

六篇走完，让我们把整张版图摊开，回望这条智造之路：

| 岗位        | 系统  | 一句话职责      | 关键能力            | 串起的跨系统流程      |
| --------- | --- | ---------- | --------------- | ------------- |
| 实施工程师     | 全景  | 客户与代码的桥梁   | 八步实施方法论、需求翻译    | —             |
| CRM 运维工程师 | CRM | 客户需求的翻译官   | CPQ、多主体、改单缓释    | 标准订单交付起点      |
| PLM 运维工程师 | PLM | 主数据源头的守门人  | ECN、BOM 比较、库存反查 | 新品研发上市、ECN 变更 |
| ERP 运维工程师 | ERP | 资源与财务的调度中枢 | MRP、财务收口、循环盘点   | 采购协同、异常闭环     |
| MOM 运维工程师 | MOM | 车间执行层的大脑   | 九大功能、工单、物流、质量   | 标准订单交付、异常闭环   |
| 系统集成工程师   | 全系统 | 让系统流动起来的血管 | 事件驱动、API、业务翻译   | 五条流程全贯通       |

数据也在这条路上完成了一次完整的闭环旅行：

```text
CRM 客户需求 → PLM 产品定义 → ERP 资源计划 → MOM 车间执行
    → 实绩回流 ERP 生成财务数据 → 交付状态回流 CRM 支撑售后 → 回到客户
```

## 结语

六篇系列写到这里，我想起系列开篇说的那句话：**实施工程师是客户与代码之间的桥梁**。

其实放到整个系列来看，每一个智造岗位，都是「桥梁」——MOM 连接计划与现场，PLM 连接设计与制造，CRM 连接市场与工厂，ERP 连接资源与账目，而系统集成工程师，连接这一切。

制造业数字化的本质，是**让数据在企业里流动起来，让每一个岗位都站在数据的正确节点上**。这套「智造工程师」系列，就是为这份理解而写。

单看任何一个岗位都只是局部，站在体系上看，才能看清制造业数字化为什么值得做、怎么做。

:::tip
把这套系列当作一张地图，而不是一本词典。地图的价值不在于背下所有地名，而在于**你知道自己在哪里、能去哪里、怎么去**。
:::
