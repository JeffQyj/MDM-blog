## AI编程的6种主流模式

2025年2月，Andrej Karpathy提出了**Vibe Coding**这个概念。但到了2026年，AI编程的玩法早已不止这一种。

程序员鱼皮把AI编程分成了6种模式，每一种都代表了一种与AI协作的方式：

| 模式                      | 一句话总结               | 上手门槛 | 适合项目规模        |
| ----------------------- | ------------------- | ---- | ------------- |
| **Vibe Coding**         | 跟着感觉走，能跑就行          | 最低   | 小项目/原型        |
| **Agentic Engineering** | 包工头模式，先规划再执行        | 中等   | 中大型项目         |
| **Harness Engineering** | 给AI套上缰绳，搭建可靠的运行环境   | 较高   | 企业级项目         |
| **Ralph Wiggum Loop**   | 写好清单让AI循环干，干完为止     | 中等   | 功能明确的中型项目     |
| **BMAD**                | 角色扮演式开发，分析师+产品+架构全上 | 中等   | 从零开始的完整产品     |
| **SDD**                 | 先写规范文档，再让AI照着做      | 中等   | 需求明确、质量要求高的项目 |

### Vibe Coding：氛围编程

Vibe Coding翻译过来就是「氛围编程」或「直觉编程」：通过自然语言和AI对话，让AI帮你写代码，你只需要描述需求、测试结果、指导方向。

你不需要精通编程语法，只需要能清楚表达你的想法，AI负责把你的想法变成可运行的代码。

这就像点外卖一样，你告诉外卖平台你想吃什么，餐厅帮你做好送到手上。你不需要会做饭，但要知道自己想吃什么。

:::caution
Vibe Coding适合做小工具、快速验证想法。做大项目？没有规划的话，迟早翻车。
:::

### Agentic Engineering：智能体工程

这是Andrej Karpathy在2026年2月提出的新概念，可以理解为Vibe Coding的「规范版」。

Vibe Coding的时候你是个DJ，放什么歌全凭感觉；Agentic Engineering里你是包工头，流程、质量、验收都得你说了算。

**一个跟着感觉走，一个按流程来。**

Agentic Engineering的思路是：先想清楚要干嘛、写好方案、拆好任务，再把活交给AI去执行，它干完了还得验收，质量不行再打回去重做。

### Harness Engineering：驾驭工程

**Harness Engineering**是2026年兴起的AI工程新范式。Harness这个词本意是「马具」，就像缰绳和马鞍用来引导强大但难以预测的马匹一样。

核心理念是**人类掌舵 + 智能体执行**——不是去优化AI模型本身，而是围绕AI智能体搭建一整套约束机制、反馈循环和工作流管理系统。

三大核心支柱：

- **上下文工程**：确保AI在正确的时间获得正确的信息，包括代码库文档、架构规范、AGENTS.md文件、测试结果等
- **架构约束**：通过代码规范检查器、自动化测试等机制，强制规定AI必须遵守的规则
- **熵管理**：定期清理AI生成代码中积累的问题，比如过时文档、命名偏差、死代码等

:::warning
模型本身已经是通用商品，真正的竞争力在于你围绕模型搭建的工程体系。同一个大模型，在不同的Harness环境下，代码质量可能天差地别。
:::

### Ralph Wiggum Loop：清单循环

这个名字来源于《辛普森一家》中那个执着不放弃的角色Ralph Wiggum。

核心思路是：把AI放在循环中反复执行，直到需求文档中的所有检查项全部完成。每轮循环都以干净的上下文开始，避免了长对话中AI容易断片儿的问题。

可以无人值守地运行——写好PRD就可以去睡觉，第二天起来检查成果就行。

### BMAD：角色化智能体开发

**BMAD**（突破性敏捷AI驱动开发方法）采用角色化智能体的方式组织开发流程：

- **Analyst Agent 分析师**：创建项目简报，包含市场分析和用户画像
- **PM Agent 产品经理**：将简报转化为详细的产品需求文档（PRD）
- **Architect Agent 架构师**：设计技术实现方案和系统架构

### SDD：规范驱动开发

**SDD**（Spec-Driven Development，规范驱动开发）强调在编码之前先创建明确的、AI能直接理解和执行的规范文档。

传统开发流程是：想到什么写什么，边写边改，最后再补文档。

而SDD的思路正好相反：**先把需求写成规范文档，并且把规范文档当作代码的唯一真相来源。**

你可以把规范文档理解为「项目宪法」。AI必须严格遵守这些条文来生成代码，确保产出完全符合预期。

### 这6种模式的关系

:::important
这些模式之间并不是互相排斥的，实际开发中完全可以混着用。比如用SDD先把规范写好，再用BMAD的角色化智能体去执行，底层用Harness Engineering的思路来约束AI的行为。
:::

## AI应用开发的5种模式

这是另一个维度的问题：怎么在你的项目里集成AI能力？

### 第一层：HTTP API直接调用

最原始、最直接的方式，就是通过HTTP请求调用大模型的API接口。

这就像打电话给一个专家咨询问题。你得自己拨号码（拼接API地址）、报上身份（传入密钥）、把问题描述清楚（构造请求体），然后等专家回答完再自己记录下来（解析响应）。

**虽然每一步都得自己来，但你对整个过程有完全的掌控。**

目前HTTP API调用主要有两种协议格式：OpenAI兼容格式和Anthropic Messages API格式。

```python
import requests

response = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers={
        "Authorization": "Bearer 你的API密钥",
        "Content-Type": "application/json"
    },
    json={
        "model": "deepseek-chat",
        "stream": True,
        "messages": [
            {"role": "system", "content": "你是一个有用的助手"},
            {"role": "user", "content": "用一句话介绍AI编程"}
        ]
    },
    stream=True
)
```

### 第二层：官方SDK调用

写过上面那段代码的同学应该能感受到，直接用HTTP调用还是挺麻烦的。填写URL、设置请求头、构造JSON、解析响应……这些跟业务逻辑压根儿没关系，但每一个都得自己处理。

所以各大模型厂商都提供了**SDK**，帮你把这些底层细节封装好了。

如果HTTP API是自己拨号打电话，那SDK就像装了一个智能通讯APP。你只管说话，APP帮你自动拨号、接通、录音、整理成文字。

```python
from openai import OpenAI

client = OpenAI(api_key="你的API密钥")

completion = client.chat.completions.create(
    model="gpt-5",
    messages=[
        {"role": "system", "content": "你是一个有用的助手"},
        {"role": "user", "content": "用一句话介绍AI编程"}
    ]
)

print(completion.choices[0].message.content)
```

### 第三层：AI开发框架

SDK解决了「怎么方便地调模型」的问题，但企业中的AI应用远不止调一下模型那么简单。

你可能还需要让AI记住之前聊过什么（会话记忆）、让AI先去知识库里查资料再回答（RAG）、让AI能调用外部工具（工具调用）、甚至让多个AI协同工作……

这些能力如果每个都自己从零开始写，工作量巨大。所以就有人在SDK的基础上又封装了一层，做成了**AI开发框架**。

打个比方：SDK相当于给你提供了发动机、轮胎、方向盘这些零件，你得自己一个一个装配；AI开发框架相当于直接给你一辆半成品车，底盘、车架、电路都搭好了，你只需要决定外观和内饰就能上路。

Python生态中，**LangChain**是目前最主流的AI应用开发框架；Java生态有**LangChain4j**和**Spring AI Alibaba**。

### 第四层：低代码平台

框架虽然功能强大，但写代码终归是有门槛的。

这时**低代码AI开发平台**就派上用场了——不用写代码也能搭出AI应用。

低代码平台就像搭积木。大模型是一块积木，知识库是一块积木，工具调用是一块积木，每块积木都是现成的，你只需要决定怎么拼接。

**Dify**是典型的低代码AI开发平台，支持通过可视化界面搭建AI聊天助手、工作流、知识库问答等应用。

### 第五层：AI编程工具SDK

2026年，Cursor、Claude Code等AI编程工具纷纷推出了自己的SDK。你可以在自己的代码里直接调用这些AI编程工具的Agent，它们能帮你读代码、改代码、跑命令。

如果说前面那些方式都是你自己动手干活，那么使用AI编程工具的SDK相当于你雇了一个会写代码的AI程序员。你只需要告诉它做什么，它会自动读文件、分析代码、完成开发。

## AI知识百科：从LLM到AGI

如果说编程方法是「术」，那AI知识就是「道」。鱼皮的AI知识百科收录了大量专业概念的解读，下面是几个核心词条。

### 什么是LLM大语言模型

大语言模型（Large Language Model，简称LLM）是当前人工智能领域最具革命性的技术突破之一。

这类模型基于**Transformer结构**，能够处理和理解人类语言的复杂模式。Transformer架构通过多层神经网络堆叠，每层都包含自注意力模块和前馈网络，使模型能够捕捉文本中长距离的依赖关系。

**模型参数量是LLM的关键特征之一。** 现代大语言模型通常包含数百亿甚至上千亿个参数，这些参数在训练过程中不断调整，最终形成对语言知识的分布式表示。

:::note
LLM的核心建立在深度学习中的**自注意力机制**之上。与传统循环神经网络相比，Transformer架构特别适合处理序列数据，通过并行计算大幅提升了训练效率。
:::

### LLM的训练过程

大语言模型的训练分为两个关键阶段：**预训练**和**微调**。

**预训练阶段**使用自监督学习方式，采用「掩码语言模型」或「自回归预测」等任务目标。模型需要根据上下文预测被遮蔽的词语，或者根据前文预测下一个可能出现的词语。

**微调阶段**则采用监督学习方式，使用特定任务的数据集进行有针对性的优化。近年来出现的「指令微调」技术，通过人工标注的指令-响应配对数据，显著提升了模型遵循人类指令的能力。
