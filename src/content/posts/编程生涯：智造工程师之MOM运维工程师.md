## 开篇承接：从「计划」走进「车间」

上一篇我们把计划排清楚了：MRP 算出了净需求，采购单下给了供应商，生产计划排到了产线。但计划只是「纸上谈兵」——真正把「生产 100 台空调」变成车间里一台台下线的机器，靠的是执行层。

而执行层的系统，就是 **MOM（Manufacturing Operations Management，制造运营管理）**。

MOM 运维工程师，就是站在这个「执行层」上，让车间每天的生产动作都跑通的那个人。

## 一、岗位画像：MOM 运维工程师做什么

**MOM 运维工程师是生产相关全模块全流程都要懂、但要优先吃透「主数据 + 生产管理 + 仓储物流」的车间大管家。**

为什么是这三个优先？因为：

- **主数据**是 MOM 的数据根基，物料、工厂、产线错了，全链路单据跟着错；
- **生产管理**是 MOM 的心脏，工单、报工、返修全在这跑；
- **仓储物流**是 MOM 体量最大的模块，物料流转的大动脉。

而计划、质量、设备是「强配套刚需」，工艺、采购、报表是「辅助支撑」。

:::warning
主数据是 MOM 的命门：物料、工厂、产线、作业员基础数据一旦出错，工单、入库、质检、设备全部跟着错——**主数据错 = 全链路单据出错**。MOM 运维上线前，第一件事永远是核主数据。
:::

### 1.1 不同角色的侧重建议

MOM 是一个多角色系统，不同岗位的侧重完全不同：

| 角色              | 重点模块              | 核心工作                       |
| --------------- | ----------------- | -------------------------- |
| **实施/运维/系统管理员** | 主数据 + 生产管理 + 仓储物流 | 优先吃透，完整跑通订单-工单-生产-入库-发货全链路 |
| **车间生产专员**      | 计划、生产、工艺、设备       | 工单报工、异常处理是核心               |
| **仓库/物流专员**     | 仓储物流 + 采购入库       | 入库、发料、盘点全流程                |
| **质量工程师**       | 质量管理              | 联动生产工单、仓储来料/成品入库质检         |
| **计划排产员**       | 计划管理              | 联动主数据、生产工单交期调整             |

## 二、Apriso 九大核心功能

达索 DELMIA Apriso 是典型的 MOM/MES 平台。根据达索官方对制造业的规划，MOM 系统通常包含九大核心功能。这九大功能就是 MOM 运维的「功能地图」：

| 序号 | 核心功能                                                   | 通俗解释                                                          |
| -- | ------------------------------------------------------ | ------------------------------------------------------------- |
| 1  | **高级排程（APS，Advanced Planning and Scheduling，高级计划与排程）** | 基于有限产能的排程优化，精确到机台与时分秒                                         |
| 2  | **数字化工艺执行**                                            | 工艺路线电子化，工序流转卡版本管理                                             |
| 3  | **生产质量管理**                                             | **SPC（Statistical Process Control，统计过程控制）**、合规追溯              |
| 4  | **生产执行**                                               | 工单、报工、返工、异常的现场执行                                              |
| 5  | **设备管理**                                               | 设备台账、点检、保养、故障、**OEE（Overall Equipment Effectiveness，设备综合效率）** |
| 6  | **工业互联应用**                                             | 通过 IoT 与设备、RFID、传感器集成                                         |
| 7  | **精益看板与生产指挥中心**                                        | 实时数据看板、指挥调度                                                   |
| 8  | **专业应用 App**                                           | 移动端、平板端、PDA 端操作                                               |
| 9  | **主数据及建模**                                             | 工厂、资源、物料、人员的基础建模                                              |

:::important
这九大功能回答了「MOM 到底管什么」。但作为运维，你要记住一个核心判断：**MOM 的价值在于把 ERP 的「计划」与底层设备的「实况」之间的断层补起来**——高级排程接住计划，生产执行落地现场，工业互联接住设备，质量追溯贯穿全程。九大功能彼此咬合，构成一条完整的制造运营链。
:::

## 三、四大核心模块

MOM 主要管理四大领域：**生产、质量、库存、维护**。对应到 Apriso 的模块：

### 3.1 生产管理——绝对核心

这是 MOM 的心脏，如果这个模块跑不通，系统就失去了存在的意义。

- 重点菜单：工单领料、报工、工单管理、工艺路线管理
- 核心职责：把 ERP 的「计划」转化为车间的「执行」
- 必须理解：工单从创建、下达、执行到完工关闭的**全生命周期**

### 3.2 仓储物流——血液流动

生产离不开物料。Apriso 的 WMS（Warehouse Management System，仓库管理系统）功能非常强大，通常与生产紧密绑定。

- 重点菜单：原材料标签补打印、合包作业、移库、拣货作业、ERP 集成-生产发料
- 核心职责：搞清楚物料如何通过条码/RFID 在系统中流动
- 必须理解：**线边仓**管理和 **JIT（Just-In-Time，准时制）** 配送逻辑

:::tip
JIT 的精髓是「按需拉动，不压库存」。传统工厂是「推式」——仓库提前备一大堆料堆在产线；JIT 是「拉式」——产线用多少，仓库送多少。MOM 里的线边仓就是为 JIT 服务的：物料从原料仓拉到线边仓，扫码消耗多少扣多少，少了自动触发补料指令。
:::

### 3.3 质量管理——合规防线

在 Apriso 中，质量往往直接嵌入生产流程（In-line Quality，线内质量），随工序自动触发。

- 重点菜单：IQC 检验任务（进料检验）、IPQC 检验任务（过程检验）、缺陷申报
- 核心职责：理解「触发机制」——收货时自动触发 IQC，某道工序完成后自动触发 IPQC
- 关键价值：**质量数据能否阻断不合格品流入下一道工序**

### 3.4 工艺管理——大脑逻辑

这是配置层，决定了生产「怎么做」。

- 重点菜单：工艺路线管理、基础工序主数据维护
- 核心职责：Apriso 基于 BPM（Business Process Management，业务流程管理），工艺路线不仅是工序排列，还包含每道工序采集什么数据、触发什么质量检查、消耗什么物料

:::note
工艺管理是最容易被低估的模块。很多 MOM 项目「生产跑不起来」，根子往往不在生产模块，而在工艺路线没配好——工序顺序错、采集项漏、物料消耗没定义。工艺是生产的「剧本」，剧本错了，演员再努力也白搭。
:::

## 四、全链路主线：订单到交付的完整路径

理解 MOM，最好的方式是沿业务流走一遍。完整的端到端主线是这样的：

```text
① 销售需求侧：销售订单变更 → 计划管理排产/调整交期 → 生成生产工单
② 生产前置：主数据（物料/工艺路线）校验 → 工单下发至生产管理
③ 物料供给：采购送货入库（采购入库+仓储IQC质检）→ 仓库按工单发料到车间
④ 车间执行：工单上料 → 工序报工 → 不良返修/生产异常处理 → 工序交接完工
⑤ 质量闭环：制程IPQC巡检、完工OQC成品检验、不良返工入库、缺陷记录追溯
⑥ 成品出库：成品入库 → 销售发货、盘点、库存对账，同步ERP
⑦ 设备保障：工单开工前设备点检、故障报修、定期保养，保障生产不中断
```

:::tip
这条主线是 MOM 运维的「地图」。遇到任何问题，先定位它在主线的哪个环节——是在物料供给卡住了，还是在质量闭环出问题了。定位准确，解决就成功了一半。
:::

## 五、三条业务主线

### 主线一：订单履行（Order to Delivery）

```text
销售订单/预测(ERP) → 计划管理(Apriso接收) → 工单生成 → 生产领料(仓储)
→ 工序报工(生产) → 成品入库(仓储) → 发货(仓储)
```

关键点：ERP 管「买什么、卖什么」，Apriso 管「怎么做、做得怎么样」。

### 主线二：物料追溯（Traceability）

```text
供应商送货 → IQC检验 → 原材料入库(生成内部标签) → 生产投料(扫描绑定)
→ 半成品/成品产出(生成新标签) → 客户发货
```

关键点：**正向追溯**（由原料查成品）和**反向追溯**（由成品查原料）。这是汽车、医药、电子行业最看重的能力。

### 主线三：异常处理（Exception Handling）

```text
生产发现缺陷 → 缺陷申报 → **MRB（Material Review Board，物料评审委员会）** 质量评审 → 返工/报废 → 返工工单/库存调整
```

:::caution
正常流程大家都会走，但系统实施成败往往取决于异常流程（缺料、设备故障、质量不合格）是否能在系统中闭环，而不是线下口头解决。
:::

## 六、三大高频业务深潜

### 业务一：工单全生命周期（MOM 核心灵魂）

工单创建 → 计划调整下发 → 车间上料投产 → 工序报工/返修 → 工序交接完工 → 工单关闭。

衍生业务还包括：工单交期变更、工单异常停机、缺料停线、返工工单处理。

:::important
工单是 MOM 的「灵魂单据」。一个工单从生到死，串联起计划、工艺、物料、质量、设备所有模块。MOM 运维的第一课，就是把工单生命周期画成状态机，每个状态转换、每个报工动作都吃透。
:::

把工单画成状态机，一眼就能看清它的一生：

```text
┌──────────┐  下达   ┌──────────┐  上料   ┌──────────┐
│  草稿/计划│ ──────→ │  已下发  │ ──────→ │  生产在制 │
└──────────┘        └──────────┘        └────┬─────┘
                                             │ 工序报工
                        ┌──────────┐  完成    ↓
                        │  已关闭    │ ←───── ┌──────────┐
                        └──────────┘         │  已完工    │
                         ▲                   └──────────┘
                         │ 返工工单           │
                        ┌──────────┐  不合格  │
                        │  返修在制  │ ←──────┘
                        └──────────┘
```

每个箭头背后都是一次系统动作：下达触发物料齐套校验，上料触发领料单，报工触发工时与良品记录，完工触发 OQC 待检。**状态机画清楚了，异常定位就快了一半。**

### 业务二：仓库物料全流转

原料采购入库 → 车间领料/工单配料 → 半成品工序流转退料 → 成品完工入库 → 销售发货出库。

配套：库存盘点、账实核对、ERP 库存同步、物料条码/标签管理。

### 业务三：全流程质量追溯

来料 IQC 检验 → 制程 IPQC 巡检 → 成品 OQC 检验 → 不良缺陷记录 → 返工返修复检。

**核心目标：出现不良可追溯到工单、产线、操作员、设备、批次原料。**

## 七、成品交付链路深潜：OQC 与组托

订单生产的终点是交付。交付前的最后两道关卡——OQC 与组托，正好横跨 MOM 的质量与仓储两大模块，是运维最常接到问题的高频现场。

### 7.1 OQC：出厂前最后一道质量关卡

**OQC（Outgoing Quality Control，出货质量控制）** 是和 IQC（进料检验）、IPQC（制程检验）并称的工厂质量「三大关口」之一，检验的是**已完工待发货的成品**。

:::note
很多工厂把 FQC 和 OQC 混用，但严格区分的话：**FQC（Final Quality Control，最终检验）** 在生产线刚下线时做（查制造质量）；**OQC** 在仓库待发区做（查包装合规性和发货配置，比如「欧版插头」别发成「美版插头」）。
:::

**检验四大项：**

| 检验项     | 具体内容                       |
| ------- | -------------------------- |
| 外观与标识   | 划痕、脏污；型号、批次号、生产日期、客户唛头是否贴对 |
| 尺寸与性能抽检 | 按 AQL（允收质量水平）标准抽样，功能测试     |
| 包装完整性   | 防潮防震、干燥剂、熏蒸标识；与组托紧密相连      |
| 随箱文件    | 合格证、说明书、出货检验报告是否齐全         |

**系统状态机流转**（MOM 运维必须画清楚——它把质量、仓储、异常三条业务串了起来）：

```text
生产完工报工 → 生成OQC待检单 → 库存「待检仓」冻结(不可发货)
    ↓ 质检判定
合格 → 待检仓→合格品仓(库存解锁，可发货/组托)
不合格 → 触发MRB(不合格评审)：
         ├─ 返工：退回车间，回到 WIP 状态
         ├─ 降级/特采：品管经理特采审批，让步放行(记录批次号便于追溯)
         └─ 报废：走报废单，核销成本
```

:::caution
一个极易踩的坑：ECN 刚生效（如换了螺丝扭矩标准），但 OQC 的检验标准（**SIP，Standard Inspection Procedure，标准检验指导书**）没在系统里同步更新，质检员拿老标准测新货，造成批量误判。**MOM 运维跟进 ECN 切换时，必须确认 OQC 检验标准已同步更新**，否则上线后必出质量投诉。
:::

### 7.2 组托：打托盘的艺术

**组托（打托盘）** 是将若干件零散货物按规则整齐码放在标准托盘上，成为便于机械化装卸、运输和存储的货物单元，业内叫**「单元化」或「成组化」**。在 Apriso 仓储模块里，对应的就是前面提过的「合包作业」——把散件合成一个可整体搬运的物流单元。

| 目的   | 说明                         |
| ---- | -------------------------- |
| 提升效率 | 散货人工一件件搬，组托后叉车一次搬运整个托盘     |
| 保障安全 | 集合成大单元降低丢失率，规范码放+缠绕膜减少碰撞损耗 |
| 优化空间 | 合理码放最大化利用托盘面积和仓库立体空间       |
| 降低成本 | 综合以上效率、安全、空间提升，显著降低物流成本    |

**组托不只是「堆」上去，更是一门学问：**

- **核心工具：托盘**——常见材质有木质、塑料等；托盘没有统一国际标准，常见尺寸有 1 米、1.1 米、1.2 米；
- **操作规范**：货物码放后**四个角要在一条直线上**；**不能超出托盘边缘**（通常要求不超 20mm）和规定高度；**不同品种、规格的货物不能混托**；
- **码放方式**：针对不同形状货物有交错式、旋转式、正反交错等技巧；易碎品或圆柱体有专门的加固和防护方法。

:::important
组托的集成意义在于：它是 MOM 仓储与 ERP 库存联动的「最后一公里」。整托出货，出库单按托生成、拣货按托执行、发货按托扫描——托盘就是最小的物流单元。

把 OQC 与组托放进「账实链条」里看，它们的坐标一清二楚：

```text
生产完工报工(MOM) → OQC待检冻结(库存冻结)
→ OQC合格 → 待检仓→合格品仓(库存解锁)
→ 组托打包(合包作业) → 销售发货单(ERP) → 发货出库(MOM实绩回传ERP)
→ 库存总账扣减 + 开票
```

**账实链条的每一环都必须有单据、有状态、有回流**——哪一环断了，月底对账就多一个差异。
:::

## 八、COE 方法论：集团多工厂的推广心法

如果你所在的企业是集团化、多工厂的，MOM 运维迟早会遇到一个灵魂拷问：**同一套 MOM，怎么在多个工厂快速推广？**

达索给出的答案是 **COE（Center of Excellence，卓越中心）方法论**：

```text
第一步：试点工厂
  基于集团典型试点工厂需求，打造 COE 核心模块，部署到试点工厂
第二步：验证沉淀
  基于试点成功经验，沉淀标准化的核心流程与主数据
第三步：批量分发
  将 COE 核心模块分发到多个分工厂，多版本管理、差异化部署
第四步：持续治理
  总部集中管控，各工厂共享最佳实践，热部署不停机
```

:::tip
COE 的价值在于「一次打造、多处复用」。它解决的是 MOM 运维最头疼的「每个工厂一套配置、越管越乱」问题——通过核心模块标准化 + 多工厂差异化部署，兼顾统一与灵活。
:::

## 九、能力要求总览：MOM 领域的成长矩阵

岗位的能力要求，可以套用一套标准的成长矩阵。MOM 领域覆盖 5 个业务维度 + 2 个平台技术维度，每个维度按「初级（了解概念）→ 中级（独立运维）→ 高级（优化创新）」分级：

| 业务/技术维度         | 初级                                 | 中级                     | 高级                       |
| --------------- | ---------------------------------- | ---------------------- | ------------------------ |

## 结语：沉淀「执行层」认知，走向「贯通层」

这一篇我们把 MOM 的执行层逻辑、九大功能、四大模块、三条主线、三大高频业务和成品交付链路串了起来。MOM 运维工程师的价值，就是**让车间每一道工序、每一批物料、每一次异常都在系统里留下痕迹，并回流给 ERP 变成真实的账**。

到这里，主线的四个环节全部就位：CRM 接需求、PLM 定义产品、ERP 排计划、MOM 执行生产。但站在车间里抬头看，你会发现一个更大的问题：**订单怎么从 CRM 一路流到 MOM？BOM 怎么从 PLM 同步到 ERP？实绩怎么从 MOM 回流成财务凭证？**

这些跨系统的「流动」，已经超出了任何一个单系统的管辖范围。
