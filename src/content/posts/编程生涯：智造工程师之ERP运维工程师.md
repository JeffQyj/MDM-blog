## 开篇承接：从「定义」走向「计划」

上一篇我们把产品定义清楚了：客户要的 100 台空调，图纸、BOM、工艺路线在 PLM 里全部就位。但定义只是「纸面完整」——真正要变成采购单、生产计划和会计凭证，还需要一个「算总账」的系统。

答案是 **ERP（Enterprise Resource Planning，企业资源计划）**。在五段式主线里，CRM 负责接需求、PLM 负责定义产品、MOM 负责现场执行，而 ERP 站在中间，是**资源与资金的中枢**——采购、财务、库存、销售、MRP 计划，全都归它管。

## 一、岗位画像：ERP 运维工程师做什么

ERP 运维工程师是**财务导向 + 业务灵活**的复合角色：

- **计划中枢**：运行 MRP，统筹采购与生产计划；
- **财务总账**：应收应付、成本核算、库存总账的最终收口；
- **跨组织协同**：多主体间订单处理。

:::note
不同于 MOM 运维的「现场感」，ERP 运维更强调**财务视角**——你的一切运维动作，最终都要能回答「这笔账平不平」。
:::

## 二、MRP Wizard：ERP 的「发动机」七步

**MRP（Material Requirements Planning，物料需求计划）** 是 ERP 最核心的运算引擎。在 SAP B1 里，它被封装成一个「向导（Wizard）」，七步定生死：

```text
MRP 运算核心逻辑：
销售订单(100台空调) + BOM(每台=1压缩机+3风扇叶+5米铜管) + 库存(压缩机20台…)
        ↓
净需求 = 订单需求 - 当前可用库存
  压缩机: 100×1 - 20 = 80台  → 生成采购建议
  风扇叶: 100×3 - 50 = 250个  → 生成采购建议
        ↓
两条分支：
  自制件 → 计划生产订单 → 下发给 MOM 生成车间工单
  外购件 → 采购申请 → 采购订单PO → 同步送货信息至 MOM 仓储
```

### 2.1 MRP Wizard 的七步关键决策

| 步骤            | 决策点                           | 常见错误                  |
| ------------- | ----------------------------- | --------------------- |
| **① 场景选择**    | 新建 vs 已有场景；新场景别删旧的，留作对比       | 覆盖旧场景，丢了对比依据          |
| **② 计划日期范围**  | 典型「今天起 60 天」；太短计划不全、太长多余建议    | 拍脑袋定日期                |
| **③ Item 选择** | 全部、按组、还是仅「MRP 参与」标记项          | 混入不参与项，建议失真           |
| **④ 数据源**     | 销售订单/报价/预测/生产订单/采购订单/库存转移     | **漏掉销售预测**是季节性生产最常见的错 |
| **⑤ 库存参数**    | 最小库存、提前期、批量大小（Item Master 配置） | 参数没维护，算出来的全是错的        |
| **⑥ 规划区间**    | 是否包含逾期订单                      | 漏掉逾期单，该补的采购不补         |
| **⑦ 结果审批**    | 逐条审查建议报告，点「批准」自动生成 PO/工单      | 全盘照单批准，不管合理性          |

:::important
MRP 通常采用「日批」模式——每天凌晨跑一次全量，白天只在紧急需求时做单向 MRP。**MRP 的时机和精度，决定了整个供应链的节奏**。
:::

### 2.2 BOM 的层级：从单层到多层

SAP B1 里 BOM 按「单层」定义，但运行时自动递归展开到最底层。以一个家具厂的 5 层 BOM 为例：

```text
床(成品)
 └─ 床垫 + 床架
     └─ 床架 → 框架 + 床头板
         └─ 框架 → 侧板 + 支撑条
             └─ 侧板 → 板材 + 封边条
```

每一层都有自己的物料、工艺和成本。MRP Wizard 会把这棵树递归展开，逐层计算净需求。**理解多层 BOM 的展开，是判断「MRP 结果对不对」的基础。**

## 三、SAP B1 的物料与库存机制

MRP 算出来的净需求，最终都要落到一次次具体的库存变动上——而每一次变动，系统都要回答「动了哪个库、走哪张单据、记哪笔账」。SAP B1 的物料与库存机制，就是这套底层规则。

### 3.1 移动类型与单据身份：SAP 的「动作指令」

SAP 运维绕不开两个基础概念，它们是理解一切库存变动的钥匙：

- **docentry**：单据的「身份证号」。每张销售订单、采购订单、生产工单创建时自动生成的唯一内部编号，是所有跨系统联动的引用锚点；
- **移动类型（Movement Type）**：每个库存操作的指令码，告诉系统「现在做什么动作、影响什么账户、生成什么会计凭证」。把 docentry 比作快递单号，移动类型就是单上的「寄件/到件/签收/退回」操作码。

| 移动类型    | 含义      | 典型场景                                                                          |
| ------- | ------- | ----------------------------------------------------------------------------- |
| **101** | 收货入库    | 采购到货入库，自动产生「借：原材料，贷：**GR/IR（Goods Receipt / Invoice Receipt，收货/发票校验清算科目）**」凭证 |
| **311** | 同一工厂内转储 | 从原料仓转到线边仓                                                                     |
| **304** | 反向发货    | 发错物料后的冲销                                                                      |
| **561** | 期初收货    | 系统上线初库存导入，只更新数量不产生会计凭证                                                        |

:::tip
移动类型的精髓：**同一个业务操作，传不同的移动类型，系统自动做不同的会计处理**。101 收货会产生会计凭证，561 期初收货不会。这对集成的启发是——你调用 SAP 接口时，移动类型就是你的业务语义，传对了一切自动，传错了财务月结对不上账。详细的黑话体系我在 [编程生涯：系统集成相关名词与业务认知](../编程生涯系统集成相关名词与业务认知/) 里讲过。
:::

### 3.2 批次与序列号：追溯的最后一公里

在医药、食品、汽车零部件等行业，**批次（Lot）与序列号（Serial Number）** 追溯是刚需：

| 追溯维度            | 粒度         | 适用            |
| --------------- | ---------- | ------------- |
| **批次（Lot）**     | 一批物料共用一个标识 | 原材料、大宗物料，按批追溯 |
| **序列号（Serial）** | 每件物料独立编号   | 成品、关键零部件，一物一号 |

SAP B1 支持按物料开启批次/序列号管理，生产工单关闭时自动绑定「哪批原料 → 哪个成品」。**这是 ECN 切换、质量召回、客户投诉追溯的底层数据基础**——追不到批次，一切质量追溯都是空谈。

### 3.3 委外加工：SAP 的两大模式

制造业绕不开「自己产能不够，发给别人做」。SAP 里委外有两大类型，运维必须分清：

| 维度   | 标准委外（委外采购）            | 工序委外（委外加工）            |
| ---- | --------------------- | --------------------- |
| 业务范围 | 整个产品/半成品的委外加工         | 生产流程中的某道特定工序          |
| 物料管理 | 管理发出原材料和收回成品，出入库做库存管理 | 精确控制工序前后在制品，出入库不做库存管理 |
| 成本核算 | 以成品/半成品为单位（材料+加工费+运费） | 基于工序计算，分摊到最终产品成本      |
| 库存标识 | 原材料库存标记「O」供应商委外库存     | 无独立库存，随生产订单流转         |

:::note
标准委外的关键是「物权不变」：发出去的料所有权还是你的，加工费只算人工和辅料。系统里体现为库存转移到「供应商委外库」——物权不变，只是物理位置变了。
:::

## 四、库存双层账与循环盘点

### 4.1 库存双层账：ERP 总账 vs MOM 实物账

这是最容易踩坑、也最能体现 ERP 运维功力的逻辑：

| 账本         | 归属  | 记录什么                        | 用途        |
| ---------- | --- | --------------------------- | --------- |
| **财务库存总账** | ERP | 库存金额、成本、财务核算                | 成本核算、财务结账 |
| **实物明细账**  | MOM | 原料仓、线边仓、半成品仓、不良仓、成品仓的每批物料流转 | 车间实物流转跟踪  |

:::warning
ERP 不记录车间工序在制、工位物料；MOM 不负责财务核算。**定期对账**（ERP 总账 vs MOM 实物账）处理在制、损耗、盘盈盘亏，是 ERP 运维的常态化工作。如果这个对账断了，ERP 里的库存就是「假」的。
:::

### 4.2 循环盘点：不停产的账实核对

传统「年度全盘」要停产，代价巨大。更先进的玩法是**循环盘点（Cycle Counting）**：

- 按 ABC 分类：A 类高价值物料高频盘，C 类低价值低频盘；
- 每天盘一部分，不打断生产；
- 系统自动触发盘点单，发现差异立即调整。

:::tip
循环盘点的精髓是「把大爆炸拆成小手术」。全年都在核账，而不是年底一次性赌一把。库存准确率是 ERP 的「血压」，循环盘点就是定期量血压。
:::

## 五、财务唯一收口：所有业务最终归集 ERP

制造企业有四套系统，但**财务数据只有一个收口：ERP**。

- CRM 销售应收、ERP 采购应付、MOM 车间工时/物料损耗/不良报废，全部同步至 ERP 完成成本、应收应付、总账核算；
- MOM、PLM、CRM 不独立产生财务凭证。

MOM 每日/实时回传实绩给 ERP：

| MOM 回传数据       | ERP 处理            |
| -------------- | ----------------- |
| 仓库出入库单据        | 更新库存总账            |
| 工单完工报工、工时、不良损耗 | 核算生产成本、完工入库       |
| 质检不良数据         | 扣减合格入库数量，生成不良损耗成本 |

## 六、多主体订单处理：集团化企业的跨组织账目

财务收口在单一主体下很简单，但落到集团化、多主体的企业里，账目要在多个法人、多个工厂之间流转，这就是 ERP 里最考验架构能力的一类业务——多主体订单处理。

「多主体」通常指**多法人公司**（同集团下的 A、B 公司）、**多工厂/多生产基地**（不同城市），以及**内外部协同方**（自有工厂与外部代工厂）。

多主体间订单处理的核心，就是解决\*\*「谁卖给谁、谁生产、谁发货、谁结算」\*\*的问题。信息流必须跨组织流转，但资金流和税务流又要严格独立。

### 6.1 三大典型场景

| 场景                 | 处理逻辑                                      | 关键动作                                       |
| ------------------ | ----------------------------------------- | ------------------------------------------ |
| **集中接单，分散生产**      | 先建「集团销售订单」，按就近生产/产能平衡规则自动拆成多个「工厂内部生产订单」   | 自动触发「跨组织销售/采购」：总部向工厂 A 下采购订单，工厂 A 向总部做销售出库 |
| **主体间物料调拨**        | 并非简单「移库」，要生成两张关联单据：A 厂「销售出库单」+ B 厂「采购入库单」 | 中间挂「内部结算价」，月底自动生成应收应付                      |
| **委托外部代工（OEM/外协）** | 下达外协采购订单时同步触发「委外发料单」，供应商完工后按「核销发料」扣减      | 发出去的料所有权还是你的，加工费只算人工和辅料                    |

### 6.2 系统处理的「四流合一」

无论哪种场景，底层逻辑都严守**「四流合一」**——实施时必须在系统里画清楚这四条线：

| 流转维度        | 处理逻辑                       | 关键单据           |
| ----------- | -------------------------- | -------------- |
| **物流（实物）**  | 明确「从哪个仓库/工位移出，到哪个」         | 调拨出库单、调拨入库单    |
| **单据流（指令）** | 上游单据驱动下游：客户订单→主体间采购订单→生产工单 | 销售订单→采购订单→生产工单 |
| **资金流（结算）** | 主体间「亲兄弟明算账」，月末跑内部开票/内部结算   | 内部应收单、内部应付单    |
| **税务流（合规）** | 不同法人间转移必须生成税务发票，与税控系统打通    | 增值税发票（内部）      |

:::warning
三大「防坑」底线：① **数据隔离**——A 厂仓管绝不能看到 B 厂库存，所有查询报表必须加「组织 ID」强制过滤；② **物料编码大一统或映射表**——否则「钢材-001」和「铁材-A型」会让系统乱套；③ **内部定价时效**——别写死固定价，要配「价目表版本」并设生效日期，否则月底财务结账因价格不对导致账目重算，那是灾难性的。
:::

## 七、两条跨系统流程

### 流程一：采购来料协同（ERP ↔ MOM 双向联动）

```text
ERP下达采购订单PO给供应商 → 供应商送货，送货单同步MOM仓储
→ MOM执行IQC来料检验：合格入库 / 不合格退货
→ 入库单、退货单实时回传ERP → ERP更新库存、形成采购应付
```

### 流程二：生产异常闭环（MOM → ERP → CRM）

```text
MOM车间缺料/设备故障/批量不良 → 提报异常，暂停工单
→ 缺料异常：反馈ERP核查采购到货进度，推动供应商
→ 质量批量不良：同步PLM核查工艺/BOM设计问题
→ 工单交期延误：ERP更新订单交期，同步CRM告知客户
```

## 八、能力要求总览：ERP 领域的成长矩阵

ERP 领域（以 SAP B1 为例）覆盖 6 个业务模块 + 1 个平台开发维度：

| 业务/技术维度           | 初级                          | 中级                                | 高级                        |
| ----------------- | --------------------------- | --------------------------------- | ------------------------- |
| **销售管理**          | 了解销售订单、报价、发货流程及多主体订单逻辑      | 优化订单管理，实现A公司采购单自动触发B公司销售订单，通过 UAT | 输出销售管理优化方案，提升订单处理效率与数据准确性 |
| **采购管理**          | 了解申购单、采购订单、库存调配全采购流程        | 基于 BOM 生成采购需求，结合库存优化采购计划          | 输出采购体系优化方案，降低无效采购成本       |
| **生产模块**          | 了解生产订单、工艺流程等 ERP 生产管理基础逻辑   | 根据订单 BOM 生成生产工单，跟进管理生产进度          | 输出生产排程优化方案，提升产能利用率        |
| **外加工模块**         | 了解委外生产、成本核算等外加工订单管理流程       | 管理外加工订单，优化过程跟踪与成本控制               | 输出外加工优化方案，降低委外成本          |
| **财务模块**          | 了解应收应付、成本核算、对账等财务管理基础概念     | 管理 ERP 财务数据，优化财务结算与报表输出           | 输出财务流程优化方案，提升财务透明度        |
| **物理库存管理**        | 了解库存盘点、调拨、批次管理等基础管理方式       | 优化库存管理，联动采购与生产提升库存周转率             | 输出库存优化方案，减少呆滞库存、提升账实一致率   |
| **SAP B1 ERP 开发** | 了解 SAP B1 基础架构、数据库结构、接口调用方式 | 开发系统插件、API 集成，优化系统运行性能            | 优化系统整体架构，沉淀可复用模块          |

:::note
注意 ERP 领域的「破局点」：**多主体间订单处理**是集团化管控的难点，也是从中级迈向高级的关键——它涉及跨公司的财务结算和物流调拨，通常需要 SAP B1 的 Intercompany Transaction 逻辑 + API 自动化。
:::

## 结语：沉淀「计划层」认知，走向「执行层」

这一篇我们走进了资源中枢：MRP Wizard 让计划自动运转，委外双模式让产能弹性扩展，循环盘点让账实持续一致，财务唯一收口让账目清晰，多主体订单处理让跨组织账目在集团内自由流转。

到这里，主线上的三个系统已经就位：CRM 接需求、PLM 定义产品、ERP 排计划。但计划终归是计划——**排产单上的「生产 100 台空调」，要靠谁来变成车间里一台台真实下线的机器？**
