## 一、闲适：工作以来的第一段留白

先交代本周的状态：**工作以来，最闲适的一周。**

这份闲适，一半来自渐入佳境。

工作顺手了。同样的需求，两个月前要琢磨半天从哪儿下手，现在拆完心里就有数，上手就做。环境熟悉了。哪条流程要找哪个部门、哪份数据躺在哪个系统、哪个问题该问哪个人——闭着眼都能摸到门。人际交往也随意了。不再拘谨，和同事打招呼、找业务部门问事情、在会议上开口，都自然了许多。

一个人和环境的关系，大概就是这样：刚来的时候，处处是陌生，处处要小心翼翼；熟悉了之后，处处是路径，处处可以放开手脚。

另一半闲适，来自一场「清仓」。

上周在[《自由》](../成长碎记自由/)里写过，加班赶完工期之后，把手上所有的需求和排期都清空了。而这一周开工发现：**本月排期的工作，竟然在加班之后，一下子全部做完了。** 于是清闲下来了。

所以，这一周，我拥有了很多很多属于自己的工作时间，能够用来提升自我。

:::note
闲适不等于无所事事。无所事事是「不知道干什么」，闲适是「有权利选择干什么」——前者是空转，后者是留白。音乐里的休止符不是没有音乐，是音乐的一部分。
:::

也正因为如此，这一篇周记，我选择了「编程生涯」而不是「成长碎记」。因为这一周的核心动作，不是又经历了什么新故事，而是把忙碌攒下的东西，做一次整体的消化。成长碎记记的是路，编程生涯沉淀的是地图。

**忙碌是输入，闲适是消化——只进不出的忙碌，叫流水线。**

## 二、术语：AI 时代的硬通货

闲适的第一站，是B站。

关键词：vibe coding 术语课。我主要看的是前端篇——有兴趣的可以自己去搜一搜。

先坦白从宽：我的前端基础，相比于后端，确实显得浅薄。但浅薄得很有特点——**不是技术栈不行，而是前端特定的术语，认不全。** React 我写过，Vue 我也用过，但前端世界那些约定俗成的「黑话」，我一直是半懂不懂的状态。

这门课干的事很纯粹：把前端术语，一个一个讲清楚。

看完的瞬间我意识到一件事：**很多时候，不是 AI 实现不了你的需求，而是你无法把你的需求，精准地描述出来。**

**术语，就是需求的压缩算法。**

| 术语   | 英文               | 一句话画像               |
| ---- | ---------------- | ------------------- |
| 骨架屏  | Skeleton Screen  | 加载时先出现的灰色占位轮廓       |
| 汉堡菜单 | Hamburger Menu   | 三条横线的折叠式导航按钮        |
| 工具提示 | Tooltip          | hover 时出现的小气泡说明     |
| 轻提示  | Toast / Snackbar | 一闪而过的操作反馈条          |
| 模态框  | Modal / Dialog   | 弹出来、挡住页面的对话框        |
| 面包屑  | Breadcrumb       | 「首页 / 分类 / 详情」的层级路径 |
| 手风琴  | Accordion        | 点击展开、再点收起的折叠面板      |
| 轮播图  | Carousel         | 自动或手动滚动的图片轮盘        |
| 进度条  | Progress Bar     | 明确展示加载进度的横条         |
| 徽标   | Badge            | 图标右上角的小红点、小数字       |

:::important
在 AI 时代，一个专业术语的价值被空前放大了：它是你和 AI 之间的**协议号**。你说出术语，AI 直接调取对应的完整实现；你说不出术语，就要花十倍的口舌去描述它，还未必描述得准。**有了 AI 之后，谁都是产品经理，谁都是全栈工程师——前提是，你说得清楚你要什么。**
:::

有人会说：这些术语，是不是刻意造出来建专业壁垒的？

以前我可能也这么想。现在我不这么看了。**刻意造出来的术语才叫壁垒，真正干活的术语，是必需品。** 就像厨师不会说「把肉放到温度比较低的油里慢慢炸，炸到外面有一层壳」，而是说「过一下油，文火，收芡」——不是装，是不这么说不行。术语存在的意义，从来不是把人挡在门外，而是让门内的人，用最短的信号，传递最准的意思。

这也呼应了我在[《从古法编程到 SDD》](../编程生涯从古法编程到sdd/)里总结过的教训：Vibe Coding 翻车的根源，是需求描述模糊。当时我给出的解法是 SDD——用结构化的规格文档把需求写清楚。如今看了术语课才意识到，**「把需求描述清楚」这件事，一半的功夫其实在于：知道并使用正确的术语。** SDD 是结构上的清晰，术语是语义上的精准，两者是同一件事的两个面。

还有一层体验，想说给「闲适」这个关键词。

同样的知识，在学校的时候，我可能懒得学，甚至厌烦学习；换到工作时间里学，竟是发自内心的自在、快乐，和满足。真的很闲适。

为什么？我想了很久，大概因为：在学校，学习是**规定动作**——课程表排好了，考试大纲划好了，你是被推着走的；在工作时间，学习是**自选动作**——排期清空之后，这段时间是公司「发还」给你的，学什么、怎么学、学多深，全由自己决定。同一个人，同一种知识，换个场景，味道完全不同。

:::caution
术语是双刃剑。只背术语不落地，会变成新的[《自以为，是》](../成长碎记自以为是/)：知道名词，不等于拥有能力。「系统面板上点亮一个图标」和「这个技能真的能用」，中间还隔着一整个业务洗礼。术语的爽感，要建立在实践的地基上。
:::

**你能说清楚，AI 才能做出来。**

## 三、人机协作：把智能体翻译进制造业

第二站，回到工作本身。这一组关键词：交互、人机协作、业务需求翻译。

背景交代：我在一家制造业公司工作，公司正在推进数智化转型。转型的抓手之一，就是各种 Agent 智能体应用的开发与落地——包括商业化 Agent 产品的协作使用。为此，公司引入了 **WorkBuddy**（腾讯推出的全场景 AI 智能体工作台），用它来支撑公司的人机协作。而我，被派遣去进行这个产品的**应用探索**。

翻译一下「应用探索」这四个字：把 WorkBuddy 的所有应用研究一遍，把它能够落地的场景，全部适配到我们公司的业务场景里。

这件事，最近有个很新奇的名字：**FDE（Forward Deployed Engineer，前沿部署工程师）**。这个岗位最早由 Palantir 首创，如今 OpenAI、Anthropic 都在大规模招聘，国内大厂也陆续跟进了。一句话概括它的内核：**普通工程师用一个能力服务所有客户，FDE 为一个客户动用所有能力。** 虽然我只是被「派」去做探索的，但做的事情确实是同一类：把智能体的能力，落进真实业务里。

而这，不是我第一次做类似的事。之前文章里提过的**设备预测性维护**：自己开发一系列机器学习算法，构建设备退化趋势预测模型，再结合 Quick BI 的 AI Pro 助手进行综合分析——从数据采集、模型预测到智能问答，就是一整套完整的智能体开发应用。

做着做着，我发现了一件很有意思的事：**学习，是一个轮回。**

还记得 AI 编程概念这两年的演进吗？最初的核心概念是**提示词工程**——怎么把话说明白，让模型听懂。然后它开始不断延伸、延伸、再延伸，延伸出一系列「工程」：[Hermes Agent](../编程生涯hermes-agent/) 的 Skills 自进化，[Loop Engineering](../编程生涯loop-engineering/) 的循环设计，[Graph Engineering](../编程生涯graph-engineering/) 的上下文图谱……概念越来越多，架子越搭越大。

但大模型越来越强之后，事情反而绕回来了：模型能力越强，瓶颈越不在模型，而在**你怎么说**。Loop Engineering 的引爆点，不就是 Boris Cherny 那句「我不再写提示词了，我写 loop」吗？可设计 loop 的第一步，依然是把目标描述清楚。转了一大圈，终极手艺还是那一个：**让 AI 准确理解你要什么。**

所以 AI 时代最主要要学的，就是**交互**——如何跟 AI 交互，去实现我们想做的事。而交互的抓手，就是**翻译**。

而「翻译」这件事，我有一个很深的体会：**在学校学的时候，和在工作里做的时候，完全是两种认知深度。**

之前在学校，提示词工程、人机协作、需求翻译这些概念，我都「学过」。但它们始终无法真正落到实处——我只能在脑子里想象「哦，把需求翻译成 AI 能懂的话」。直到工作里，真的完成了需求、真的把应用落地、业务部门真的在生产中使用之后，这些结果会反过来印证：你脑子里的概念，是不是真的有物。**落地的结果，是概念的最终考试**——考不过，就逼着你回去把概念重新打磨得更清晰。

这就是[《自以为，是》](../成长碎记自以为是/)里那道「我以为」和「是」之间的沟：学校里的知识，是「我以为我知道」；落地之后的知识，才是「我确认我知道」。理论和实际之间的距离，只能用真实的业务去缝合。

:::caution
**Demo 能跑 ≠ 生产可用。** 智能体应用的真正考验，从来不是「做出来」，而是「用起来」——业务部门愿不愿意用、用得顺不顺、能不能沉淀进日常工作流，才是验收标准。这也是人机协作在制造业的「最后一公里」：模型很聪明，产品很强大，但业务场景的适配，一步都省不掉。
:::

**人机协作的本质是翻译——把业务的语言，翻译成 AI 的语言。**

## 四、沉淀：给成长飞轮装上变速器

现在，说到本周的主题：**沉淀。**

先说一个变化：经过真实项目业务的洗礼之后，看待需求、看待沉淀知识的视角，完全不一样了。

以前看一个前端名词，它就只是一个名词——考试要考的那种名词。经过业务洗礼之后，再看它，我知道它应用在哪里、解决什么问题、什么时候该请它出场。**它是真的有用的术语，而不只是书面上的一个词。** 理论和实际之间的那段距离，被业务亲手缝合了。

视角变了，接下来就能做两件事。

**第一，审视。** 审视自己有哪些还没触及的地方、哪些地方还有缺陷。像一个刚打完仗的士兵，回头清点装备：哪些武器用顺手了，哪些还没开过封。

**第二，评估。** 评估自己的综合能力，评估自己现在的价值。这件事很重要——因为人不可能在一份工作上一直干下去。人挪活，树挪死，人一定是求变的。尤其我还年轻，我追求的一定是自身能力的成长，而不是一份工作的稳定。哪天如果让我发现，目前的工作无法再让我提升能力、无法再让我的技术增长——那我只会选择，往上走。

而「评估自己」，需要一个模型。这周我找到的模型是：**成长飞轮。**

有人可能会说：一直工作，不就等于成长飞轮一直在快速旋转吗？

是，也不是。

确实，忙碌让成长飞轮转得飞快——业务推着人跑，学这个、学那个，快速上手、快速落地，转速拉满。**但如果成长飞轮一直转得飞快，它一定会脱轨。** 它甚至会偏离方向，甚至转速、转法，都不是你想要的那种。

所以真的需要一些时间，把成长沉淀下来、内化到自己身体里——**那才是真的成长。**

飞轮矫正回来之后的感觉，很难形容，但我找到了两个游戏化的说法：

- **扫盲的爽感**：原来这个术语是这个意思、用在那里——盲区被一格一格点亮，地图上的黑雾一片片消散。
- **系统面板加点的爽感**：好像对整个人，有了一个 RPG 式的系统面板——哪项能力值多少、哪里加过点、哪里还是初始值，清清楚楚。

地球 online 不显示进度条，那就自己调一个出来；人生 online 不显示属性面板，那就自己画一个出来。

:::warning
**把忙碌当成长，是飞轮脱轨的前兆。** 忙碌确实产生经验，但经验不会自动等于成长——未经沉淀的忙碌，只是重复。如果你发现自己「每天都很忙，但说不清比上个月强在哪」，这就是飞轮空转的警报。
:::

:::caution
反过来，沉淀也不是躺平的借口。沉淀是主动的消化，不是被动的停摆。校准飞轮的目的，是让下一轮转得更快、更稳，而不是把飞轮拆了供起来。闲适是留白，不是空白。
:::

**成长飞轮不能只有转速，还要有校准。**

## 五、自然语言与多模态：编程的道与翼

最后一组关键词：自然语言、多模态的重要性。

先说一个可能有点暴论的结论：**AI 时代，学哪个语言，真的不重要。**

重要的，是一个核心的**编程思维**。编程思维有了之后，语言在 AI 时代来说，没有任何门槛。因为所有语言的语法，是基本通用的；而所有语言的编程思维，更是完全一致的。循环还是循环，条件还是条件，抽象还是抽象——换一门语言，只是换了一套拼写。

掌握了一个「道」，其他语言的分支，只是「术」的不同——道和法，完全一致。

:::note
这个暴论需要备注边界：不重要的从来不是语言，而是**语法记忆**——AI 把「背语法」的门槛干掉了，但干不掉「编程思维」本身。抽象、分解、循环、条件、状态，这些思维依然要在真实的工程里，一行一行代码地长出来。这和[《从古法编程到 SDD》](../编程生涯从古法编程到sdd/)的结论是一致的：懂技术的人，才能更好地驾驭 AI。
:::

那再往深问一层：所有语言归根到底的「道」，到底是什么？

我的答案是：**自然语言。**

想想编程语言的来历。我们为什么要发明各种编程语言？不就是为了跟机器交互吗？从机器码到汇编，从汇编到高级语言，从高级语言到低代码——一路都在往同一个方向走：**让人说人话，机器懂人话。** 交互的门槛，一路在降。

而 AI 时代的模型发展，第一次让「人话」本身，成为了编程语言。

用代码跟机器交互的时代，是「古法编程」的时代——这是[《从古法编程到 SDD》](../编程生涯从古法编程到sdd/)里的说法。从 PTA 纯手敲，到 CV 工程师，到 Tab 工程师，到 Vibe Coding，一路演进到现在：**现在的时代，一定是自然语言的时代。** 而自然语言时代的核心技能，归根到底，还是提示词工程。

你会发现，今天沉淀下来的所有内容——术语是需求的压缩算法，翻译是业务到 AI 的桥，交互是人机协作的通道——**全部都是提示词工程的一部分。**

最后，说说**多模态的重要性**——它也是提示词工程的一部分。

很多需求，你用文字就是描述不清楚。比如「我要一个高级感一点的页面」「这个间距再呼吸一点」——什么叫高级？什么叫呼吸？

没关系。直接截个图，发给模型：**「我想要跟这张图展示的一样的效果。」**

:::note
你没有用文字描述，但你依然把需求表达得清清楚楚：你要的是这个效果，而不是其他任何效果。**提示词不一定是文字——一切能精准传达意图的媒介，都是提示词。** 文字擅长表达逻辑与结构，图片擅长表达视觉与样式；会截图，也是一种会表达。能用一张图说清的需求，就别用一千句「高级感」折磨彼此。
:::

自然语言是道，多模态是翼——一个让人和机器对话，一个让表达的维度展开。

**未来的编程语言，是你现在说的每一句话。**

## 结语：沉淀，才能，顶峰相见

最后解释一下，为什么这一篇周记，从「成长碎记」变成了「编程生涯」。

因为我认定，它是我编程生涯的一个**重要节点**。

在忙碌的工作之后，闲下来、能够自我沉淀的这个时候，才真的让我感觉到：工作带给我能力提升的意义。如果没有这个沉淀，工作可能真的就是一条流水线——我只能说，我做了哪些业务、实现了哪些需求。但工作回馈到自身的成长、整个思维框架的升级、整个人的能力升华——如果没有沉淀，是总结不出来的。

坚信那一句话：**快即是慢，慢即是快。**

业务不断地逼迫我：快速地学这个、快速地学那个，快速地掌握技术应用，快速地把需求落地——这是一方面的成长，是「快」。闲下来、能够自我沉淀的这段时光，让整个思维体系再进行一次升华，再反哺回我整个能力体系——这是另一方面的成长，是「慢」。一快一慢，一急一缓，才是完整的成长节奏。而把这一切记录下来，让今天看得见的成长，成为明天可以回望的坐标——这，就是[记录的力量](../个人杂谈记录的力量/)。

第十周了。回头看，这十周像一场越转越快的飞轮：

- 第一周，「**匹配期待**」——把主动权握回自己手里；
