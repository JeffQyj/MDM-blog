如果用一句话形容 2026 年的编程工具格局，那就是：**Claude Code 在终端里替你写代码，你在旁边当 reviewer。**

## 一、初见 Claude Code：终端里的 AI 员工

先讲一个场景。

2023 年你问 ChatGPT「帮我写个博客系统」，它给你输出一大段代码。你复制到 IDE，跑起来——报错。你把报错粘回去，它又给你一段新代码。如此反复，像两个人在窗户两边比划。

2025 年你打开 Claude Code，说「帮我写个博客系统」。它先问你要什么技术栈，然后出个计划，确认后自己创建文件、安装依赖、跑起服务。中间你说「换个主题色」，它直接改 CSS 文件，不用你动手。

这就是从 **AI 对话助手**到 **AI Agent** 的本质跨越：前者只会说，后者会动手。

**Claude Code**（社区常简称为 CC）是 Anthropic 在 2025 年 2 月推出的终端原生 AI Agent 程序。它运行在你的终端里，能读写本地文件、执行 Shell 命令、安装依赖、调用 API——**感觉就是雇了一个能看懂代码的实习生，直接坐在你的电脑前面干活。**

### LLM Loop：Agent 运作的灵魂

Claude Code 能「自主干活」的核心机制，叫做 **LLM Loop（大模型循环）**。

理解它，只需要看这张流程图：

```text
用户输入任务
    ↓
初始化消息列表(系统提示 + 用户任务 + 工具清单)
    ↓
循环开始(条件：未停止 && 未超过最大步数)
    ├─ 构建包含当前状态的提示词
    ├─ 调用大模型
    ├─ 解析模型响应
    │   ├─ 如果是工具调用指令 → 执行对应工具
    │   └─ 如果是最终答案 → 结束循环
    ├─ 将工具执行结果追加到消息列表
    └─ 进入下一轮循环
    ↓
循环结束，返回最终结果
```

每一次循环，Agent 都在做「**思考 → 行动 → 观察 → 再思考**」的闭环。这个模式在 AI 领域有一个专门的名字——**ReAct（Reasoning + Acting）**，在「[编程生涯：Agent 原理及其开发框架全览](../编程生涯agent原理及其开发框架全览/)」里我完整拆解过它的最小可运行代码实现。

### 为什么不是网页版 AI？

有人会问：ChatGPT 也能连工具啊，有什么区别？

区别在于两点：

| 维度             | 网页版 AI          | Claude Code             |
| -------------- | --------------- | ----------------------- |
| **运行环境**       | 云端沙箱，看不到你的文件    | 本地终端，能直接读写你的项目          |
| **工具权限**       | 有限的预置工具（搜索、画图等） | 完整的 Shell 权限 + 40+ 内置工具 |
| **任务持续性**      | 单轮对话，每次都要重新说    | 多轮循环，自主规划执行             |
| **Harness 工程** | 基础              | 顶尖                      |

第二点特别值得展开。**Harness** 是最近 AI Agent 圈非常火的概念——指 Agent 程序中「除了大模型本身之外，所有让 Agent 表现更好的工程设计」。Claude Code 的 harness 做得有多好？它的源码泄露后，人们发现里面有五级压缩策略、三层记忆架构、读写分离的并发控制——全是经典的计算机工程思想。这一点我们后面慢慢拆。

:::note
Claude Code 并不绑定 Claude 模型。你可以通过环境变量配置使用国产模型（如通义千问、GLM、MiniMax 等）来驱动它，它是一个**通用的编程 Agent 框架**，换模型不换能力。
:::

## 二、从零上手：搭建你的第一个编程 Agent

理论聊完了，动手。

### 安装方式

两种方式，选一个就行。

**方式一：一行命令安装**

打开终端，执行：

```bash
npm install -g @anthropic-ai/claude-code
```

安装完后验证：

```bash
claude --version
```

看到版本号就说明成功了。

**方式二：让 AI 帮你安装**

如果你用 Cursor 或 Trae 这类 AI IDE，可以直接对它说「帮我安装 Claude Code」，它会自动处理下载和依赖问题。

### 模型配置

安装之后要配「大脑」——你想让 Claude Code 用哪个模型来驱动。

```bash
# 如果你有 Claude 订阅
claude login

# 如果你想用 API Key
# 设置环境变量即可
set ANTHROPIC_API_KEY=sk-xxx  # Windows PowerShell
```

:::tip
推荐安装 [cc switch](https://github.com/anthropics/cc-switch) 来做多模型管理，支持在高中低三档模型中自由切换，方便国产模型和官方模型混用。
:::

### 三种权限模式

这是 Claude Code 最核心的交互设计。用 **Shift + Tab** 可以在三种模式间循环切换：

| 模式         | 显示状态              | 行为              |
| ---------- | ----------------- | --------------- |
| **默认模式**   | `? For shortcuts` | 最谨慎，每次文件操作都询问   |
| **自动编辑模式** | `Accept edits on` | 自动修改文件，但执行命令仍询问 |
| **规划模式**   | `Plan mode`       | 只出方案不改代码        |

我的建议：日常用默认模式，重构大动作前切到规划模式先看方案，信任建立后切自动编辑模式提升效率。

如果你追求极致效率，可以用 `--dangerously-skip-permissions` 参数启动——跳过所有权限确认。但官方把 "Dangerously" 写在脸上是有理由的，慎用。

### 实战：一句话做番茄钟

装好了来试一把。创建一个新目录，启动 Claude Code：

```bash
mkdir my-tomato
cd my-tomato
claude
```

然后输入：

```
帮我做一个桌面的番茄钟应用
```

Claude Code 会先主动问你要什么技术栈（因为它发现你的指令比较模糊），然后进入规划模式出一份方案，确认后开始创建文件、安装依赖、运行。

整个过程你只需要点几次确认，三分钟后一个能用的番茄钟就出现在屏幕上了。

这就是 Claude Code 的魅力——**你说意图，它干活，你做 reviewer。**

### 基础交互技巧

用熟了之后，这几个技巧能让你效率翻倍：

**@ 文件传上下文**

```bash
# 直接 @ 文件路径，让 AI 精准读取
帮我 review 一下 @src/main.ts 的代码逻辑
```

**拖拽图片利用多模态**

直接把设计稿截图拖进终端，Claude Code 能识别图片内容，按你的配色和布局修改代码。

**斜杠命令速查**

```bash
/help    # 查看所有命令
/model   # 切换模型档位
/compact # 压缩上下文
/rewind  # 回滚操作
/btw     # 问个无关问题（不污染上下文）
```

:::important
给 Claude Code 的指令越短，它花的 token 反而可能越多——因为上下文不足时，它需要自己去探索项目文件来理解意图。**写得越具体，执行越精准，token 越省。**
:::

## 三、管住它：回滚、上下文与记忆管理

用 Claude Code 久了，一定会遇到两个问题：**改坏了怎么办？**、**用久了怎么变笨了？**

### 后悔药机制

Claude Code 自带一个快捷回滚——按两下 ESC 或输入 `/rewind`，可以选择回滚对话、回滚文件修改、或者两者都回滚。

但它的回滚有局限：**只能撤销 Claude Code 自己写入的文件，终端命令生成的文件（比如 npm install 创建的文件）是撤不掉的。**

真正靠谱的后悔药是 Git。把 Git 当成游戏的存档系统，每完成一个里程碑就让 Claude Code 帮你提交一次。

```bash
# 让 Claude Code 帮你初始化 Git 并提交
帮我初始化 git 仓库，并提交当前版本
```

有了 Git 兜底，你就可以放心让 Claude Code 尝试各种方案了。

### 上下文为什么会「变笨」

这是一个绕不开的问题。Claude Code 的大脑也是大模型，而大模型的上下文窗口是有限的。

每轮对话、每次文件读取、每个工具调用结果，都累积在上下文里。上下文越满，模型的有效注意力就越稀释——就像你脑子里塞了太多东西，反而抓不住重点。

```text
上下文占用率：0%                        100%
                ├────────────────────┤
                ↑                  ↑
          新对话时             超过 60% 建议压缩
```

监控上下文有两种方式：

```bash
# 查看详细上下文报告
/context

# 打开底部百分比显示（需先让 CC 帮你配置）
帮我开启上下文百分比显示
```

我个人的习惯是：**超过 60% 就主动 /compact 一次。**

压缩有两个命令，作用不同：

| 命令         | 效果          | 适用场景    |
| ---------- | ----------- | ------- |
| `/compact` | 压缩对话，保留关键信息 | 任务阶段转换时 |
| `/clear`   | 彻底清空，重开对话   | 前后任务无关时 |

### 三层记忆架构（源码级）

这是 Claude Code 源码里最精妙的设计之一，也是它「越用越懂你」的根本原因。

Claude Code 的记忆不是一块铁板，而是分了三层，**不同温度的数据用不同的方式管理**：

```text
第一层：memory.md 索引
    ├─ 始终加载到上下文
    ├─ 限制：200 行 / 25KB
    ├─ 只存指针不存内容（每行 ≤ 150 字符）
    └─ 超过限制时截断，并告知 AI 索引不完整

第二层：话题文件
    ├─ 按需加载（最多 5 个）
    ├─ 由小模型根据当前对话主题选择
    └─ 存编码偏好、项目约定、踩坑记录

第三层：历史对话
    └─ 用 grep 搜索关键词检索
```

设计哲学有两个关键点：

1. **记忆不记代码**。因为代码频繁变化，但记忆不会自动更新。如果记忆里写着「函数 X 在第 30 行」，重构后就变成误导信息。所以 Claude Code 只记人的偏好和项目约定，代码永远实时读取源码——**从根源上消灭了缓存与数据不一致的问题。**
2. **索引 + 按需加载**。memory.md 像一本书的目录，每次对话都加载但只占很小空间。具体内容存在话题文件里，AI 觉得需要的时候才去读。

:::caution
很多用户以为关掉会话就等于「记忆清零」了。其实 Auto Memory 功能打开后，Claude Code 会在后台默默记录你的偏好和反馈，存在 `.claude/memory/` 目录下。如果你换项目或换电脑，这些记忆不会自动迁移。
:::

## 四、个性化定制：让 Claude Code 记住你

Claude Code 对每个人都是一张白纸，但你可以通过三种方式让它「越来越懂你」。

### CLAUDE.md 三层体系

这是最重要也最容易被新手忽视的功能——**项目的「说明书」**。

```text
CLAUDE.md 三层结构
├─ 全局层 (~/.claude/CLAUDE.md)
│   └─ 永远说中文、输出格式偏好、个人习惯
├─ 项目层 (项目根目录/CLAUDE.md)
│   └─ 技术栈、项目结构、编码规范、关键约束
└─ 子文件夹层 (子目录/CLAUDE.md)
    └─ 该目录下的特殊规则
```

用 `/init` 命令自动生成项目级的 CLAUDE.md：

```bash
# Claude Code 会自动扫描项目结构并生成说明书
/init
```

生成后打开看看：

```markdown
# 项目概览
- 技术栈：React + TypeScript + Vite
- 构建命令：npm run build
- 开发命令：npm run dev

# 编码规范
- 使用双引号
- 缩进 2 空格
- 组件使用函数式 + TypeScript

# 注意事项
- 修改数据库配置前必须询问
- API 请求统一通过 src/api/ 目录
```

### Auto Memory：自动记录的「隐形笔记」

开启方式很简单：

```bash
/memory
# 选择 "Turn on auto-memory"
```

打开后，Claude Code 会在后台默默记录：

- **关于你**：你是 Java 后端、习惯 Spring Boot
- **你的反馈**：你不喜欢浅色 UI、代码里少用 any
- **项目信息**：当前进度、决策记录、技术选型

这些记忆以文件形式存在 `.claude/memory/` 目录下，新对话开始时只会先加载索引，具体内容按需读取——不占用宝贵的上下文窗口。

### 自定义参考文档

除了 CLAUDE.md 和 Auto Memory，你还可以自己建文档，告诉 Claude Code 什么时候去读。

比如建一个 `brand-guide.md`：

```markdown
# 品牌视觉规范
- 主色：#1890FF（科技蓝）
- 辅助色：#52C41A（成功绿）、#FF4D4F（危险红）
- 字体：PingFang SC, 14px
- 圆角：4px
```

然后在 CLAUDE.md 里加一句：

```markdown
修改前端样式时，参考 brand-guide.md 中的视觉规范。
```

**这三种记忆机制配合使用**：CLAUDE.md 是主动立的规矩，Auto Memory 是过程中积累的经验，自定义文档是随时可查的参考资料。一起用，Claude Code 才会越来越像「你的」助手。

:::tip
不需要一上来就把 CLAUDE.md 写完美。最佳实践是：**项目有雏形后生成初始版，使用过程中踩的坑再逐步补充进去。** 这样积累下来的规则才真正有用。
:::

## 五、高级拓展体系——让 Agent 真正强大

CLAUDE.md 和记忆只是「规则层」的定制。要让 Claude Code 真正干大事，需要用到它的高级拓展体系。

### 5.1 Skills——AI 的专业说明书

**Skill** 是什么？简单说就是**给大模型看的专业领域操作手册**。

它不等于插件或工具，它是告诉 AI「遇到这类问题，按这个流程来操作」的说明书。分四种类型：

| 类型      | 说明           | 示例             |
| ------- | ------------ | -------------- |
| **知识型** | 领域知识手册       | 前端设计规范         |
| **流程型** | 标准化操作流程      | 报销流程指南         |
| **工具型** | 工具调用说明       | Nano Banana 生图 |
| **混合型** | 知识 + 流程 + 工具 | 公众号排版发布        |

Skill 不像 CLAUDE.md 那样每次都加载进上下文，它只会在启动时加载几行元信息（名称 + 触发描述）。当 AI 觉得当前任务匹配某个 skill 时，才会去加载完整内容。

安装方式：

```bash
# 方式一：手动放置
# 把 skill 文件夹放到 .claude/skills/ 目录下

# 方式二：用 find-skill 自动搜索安装
帮我找一个前端优化的 skill
```

你可以用官方的 **Skill Creator** 创建自己的 skill。它会通过对话引导你一步步完成——想好 skill 要解决什么问题，然后描述给它即可。

:::note
Skill 和后面要讲的 SubAgent 最大的区别在于上下文管理方式。Skill 共享主对话的上下文，适合轻量任务；SubAgent 拥有独立上下文，适合重型任务。后面会详细对比。
:::

### 5.2 MCP——通用的工具转接头

**MCP（Model Context Protocol）** 是 Anthropic 在 2024 年 11 月推出的开放协议，目标是统一「大模型 ↔ 工具/数据源」的通信方式。

它要解决的问题很简单：**每个 Agent 框架都要重复实现一遍「天气工具」「搜索工具」「数据库工具」，太累了。** MCP 出现后，工具按协议开发一次，所有支持 MCP 的框架都能直接用。

我在「[独立项目：AI 天机学堂+MCP 协议+MyManus 智能体](../独立项目ai天机学堂mcp协议mymanus智能体/)」里做过完整的 MCP Server 实战，从原理到自定义部署一行行代码拆过。这里只讲一个实际场景。

**实战：连接 Figma MCP 还原设计稿**

```bash
# 安装 Figma MCP Server
npx @anthropic-ai/mcp-server-figma

# 在 Claude Code 中查看已安装的 MCP 工具
/mcp
```

配置好鉴权后，直接把 Figma 设计稿链接丢给 Claude Code：

```
修改当前页面，使其与 Figma 设计稿保持一致
https://www.figma.com/file/xxx
```

Claude Code 会自动调用 Figma MCP 的两个工具：`get design context` 获取组件信息和 `get screenshot` 获取设计稿截图。相比「传图片让 AI 照着做」的方式，MCP 能拿到精确的字体大小、间距、颜色值——**还原度直接从「大概像」变成「几乎一模一样」。**

### 5.3 CLI 工具——轻量级外部连接

2025-2026 年有一个明显的趋势：**很多原本做成 MCP Server 的工具，正在转向 CLI 工具。**

原因很简单：MCP 占用 token 较大，而 CLI 工具更轻量。AI 本来就很擅长操作命令行——输出一行命令比模拟人类点击网页要精准得多。

比如 **Open CLI**，它把很多社交媒体和网站的接口包装成了命令行工具：

```bash
# 让 Claude Code 安装 Open CLI
帮我安装 Open CLI 工具

# 然后直接让它用
帮我查一下小红书上深圳必吃的餐厅
```

Claude Code 会调用 Open CLI 搜索社交媒体内容，把结果整理给你。这在没有配置任何 MCP 的情况下就能做到。

### 5.4 SubAgent——并行分身

SubAgent 是 Claude Code 里最容易被低估的功能。它有一个**完全独立的上下文空间**。

想象一个场景：你正在做一个电商项目，想让 Claude Code 调研一下竞品方案。如果让主 Agent 去做，它得停止写代码，串行调研，而且调研的中间过程会塞满上下文——做完调研后它写代码的能力反而下降了。

SubAgent 的解法是：**派个分身去调研，分身在自己的上下文里干活，调研完只把结论汇报回来。** 主 Agent 的上下文干干净净，不受影响。

```bash
# 创建 SubAgent
/agent
# 选择 "Create new agent"
# 描述它的职责，选择可用工具和颜色
```

创建完成后，你可以在提示词里直接指定：

```
让代码审查 SubAgent 帮我 review 一下当前的改动
```

| <br />   | Skill       | SubAgent   |
| -------- | ----------- | ---------- |
| **上下文**  | 共享主对话       | 独立上下文      |
| **适用场景** | 轻量、与当前任务关联大 | 重型、不希望污染主线 |
| **典型用例** | 写每日总结、格式化代码 | 代码审查、竞品调研  |

### 5.5 Hook 与 Plugin

**Hook** 是条件触发器——当某个事件发生时，自动执行一段逻辑。

比如「每次 Claude Code 修改完文件后，自动用 Prettier 格式化」：

```bash
# 进入 Hook 配置
/hooks

# 选择 "Post-use"（工具使用后）
# 选择 "Write" 或 "Edit" 工具
# 输入格式化命令
jq '.filePath' | xargs npx prettier --write
```

Hook 可以保存在三个级别：

| 级别 | 配置文件                | 作用范围     |
| -- | ------------------- | -------- |
| 本地 | settings.local.json | 仅本机      |
| 项目 | settings.json       | 随 Git 分发 |
| 用户 | 用户目录配置              | 全局生效     |

**Plugin** 则是「全家桶安装包」——把 Skill、SubAgent、Hook、MCP 打包在一起，一键安装。

```bash
# 浏览插件市场
/plugin
# 选择 "Discover" → 安装 "Frontend Design"
```

装完后，Claude Code 的前端设计能力会有质的飞跃——默认的「深紫 AI 风」会被替换成更现代、更协调的 UI 风格。

:::important
高级拓展体系的核心原则是：**把「一问一答」变成「系统驱动」**。不要每次都让 AI 从头理解你的需求，而是通过 Skill、CLAUDE.md、Plugin 构建一套可复用的能力体系。这才是使用 Agent 的「高阶姿势」。
:::

## 六、源码视角：Claude Code 凭什么最好用

Anthropic 的一次工程失误导致 Claude Code 约 51 万行 TypeScript 源码通过 npm Source Map 意外泄露。开发者社区把它奉为「AI 应用架构的最佳教材」。

下面我们从源码角度看看，Claude Code 内部到底长什么样。

### 6.1 六层分离架构

整个项目采用 React Ink 框架（在终端里用 React 写界面），从上到下分为六层：

```text
┌──────────────────────────────┐
│  CLI 与界面层                 │ ← 你看到的所有交互
├──────────────────────────────┤
│  Agent 循环引擎               │ ← "大脑"，核心循环
├──────────────────────────────┤
│  工具系统（40+ 内置 + MCP）     │ ← "手脚"
├──────────────────────────────┤
│  记忆系统                     │ ← 分层记忆，解决失忆
├──────────────────────────────┤
│  上下文压缩系统                │ ← 五级压缩，节省 Token
├──────────────────────────────┤
│  权限与安全系统                │ ← 多层审查，保障安全
└──────────────────────────────┘
```

### 6.2 核心引擎：一个 while 循环撑起整个 Agent

打开负责核心对话循环的 `chat.ts`，你会发现最核心的代码出人意料地简洁——**就是一个** **`while`** **无限循环。**

```typescript
// 核心对话循环（简化示意）
while (!isDone && stepCount < MAX_STEPS) {
    // 1. 上下文压缩（如果需要）
    compressContextIfNeeded();

    // 2. 调用大模型
    const response = await callModel(messages);

    // 3. 解析响应
    if (response.hasToolCalls()) {
        // 执行工具调用
        const results = await executeTools(response.toolCalls);
        messages.push(...results);
    } else {
        // 任务完成
        isDone = true;
    }

    stepCount++;
}
```

这就是前面讲过的 **ReAct 机制**在代码层面的真实样子——每轮「思考 → 行动 → 观察」，直到任务完成。

在这段代码上方，还留着 Anthropic 工程师写的一段「巫师守则」注释：

```typescript
/*
 * 年轻的巫师，请遵守以下三条关于 thinking block 的规则：
 * 1. ...
 * 2. ...
 * 3. ...
 * 否则，你将受到整整一天 debug 和薅头发的惩罚。
 */
```

一时间分不清这是程序员的浪漫还是 AI 的浪漫。

### 6.3 读写分离的工具并发

Claude Code 内置了 40 多个工具。当 AI 同时想读三个文件再改一个文件时，这些操作怎么调度？

源码里的答案是**读写分离**：

- **多个只读工具**：并行执行，互不阻塞
- **写操作**：必须排队，等前面的只读操作全部完成
- **并发上限**：默认最多 10 个工具同时并发

更重要的是**默认拒绝策略**。在工具注册函数 `buildTool` 中，`isReadOnly` 和 `isConstrainedSafe` 都默认为 `false`：

```typescript
function buildTool(config: ToolConfig): Tool {
    return {
        // 如果没有声明安全属性，默认视为不安全
        isReadOnly: config.isReadOnly ?? false,
        isConstrainedSafe: config.isConstrainedSafe ?? false,
        // ...
    };
}
```

也就是说：**如果某个工具的开发者忘了声明「我只是读文件，不会改东西」，系统默认把它当危险操作处理。** 这种「失败时关闭」的安全哲学，在 AI 行为不可预测的场景下，比「默认允许」安全太多了。

### 6.4 五级上下文压缩 + 断路器

上下文管理是 Claude Code 工程上最见功力的部分。它设计了**五级漏斗式压缩策略**，从轻到重依次触发：

```text
第一级：裁剪（最轻）
    └─ 把旧的工具调用结果只保留结构，不保留内容

第二级：微压缩
    └─ 把体积大的工具执行结果卸载到缓存

第三级：上下文折叠
    └─ 对中间对话做摘要，只保留关键信息

第四级：自动压缩
    └─ 上下文占用超阈值时，触发全量摘要

第五级：应急压缩（最重）
    └─ API 返回 413 提示词太长时紧急触发
```

这里最让我印象深刻的是**断路器机制**。

解决方案很经典：

```
连续压缩失败 3 次 → 断路器打开 → 停止自动压缩
```

这就是经典的「熔断」思想在 AI 工程里的应用。

### 6.5 三层安全审查

很多用户以为开启 `--dangerously-skip-permissions`（YOLO 模式）后 Claude Code 就完全不设防了。但源码显示，**即使 YOLO 模式下，后台仍有一个独立的 AI 分类器在帮你把关。**

```typescript
// yolo-classifier.ts
// YOLO 模式下不可见的影子审查
const result = await yoloClassifier.classify(toolCall);
if (result === "reject") {
    // 即使 YOLO 模式也会拦截高危操作
    return "此操作已被安全系统拒绝";
}
```

一次工具调用至少经过五层安全检查：

```text
工具调用请求
    ↓
① 工具级别的安全属性声明
② 影子分类器审核（YOLO 模式下仍生效）
③ Bash 命令严格规则校验（20+ 种规则）
④ 用户权限确认（非 YOLO 模式）
⑤ 执行结果安全检查
```

没出过事故的背后——是多层机制在负重前行。

### 6.6 Feature Flag 泄露的未来路线图

源码中遍布的 `featureFlag` 开关无意中泄露了 Claude Code 未来的产品路线图：

| 功能代号                 | 说明               |
| -------------------- | ---------------- |
| **Caros（长期助手）**      | AI 可 24 小时持续运行   |
| **Auto Dream（自动做梦）** | 白天干活记笔记，晚上自动整理记忆 |
| **多 Agent 协作**       | 一个 AI 指挥多个 AI 干活 |
| **语音模式**             | 语音交互             |
| **浏览器操作**            | 操控浏览器            |

其中最浪漫的是「自动做梦」——AI 白天帮你干活，晚上离线整理记忆，像人一样「日有所思，夜有所梦」。

### 6.7 反蒸馏与卧底模式

Anthropic 为了防止竞争对手通过录制 API 流量来蒸馏 Claude Code 的能力，在源码里埋了一套相当「绝」的防御机制——**往 API 请求里注入假的工具定义。**

竞争对手如果录制输入输出训练自己的模型，训练出来的模型在工具调用上会越来越差。这不是防守，是反间计。

另外，Anthropic 内部员工用 Claude Code 往开源项目提交代码时，会自动启用「卧底模式」——防止内部信息（模型代号、未公开功能）通过开源贡献泄露出去。这个模式默认开启，只有仓库被确认为内部仓库时才会关掉。

## 七、工程哲学的启示

看完 Claude Code 的源码，一个很深的感触是：

**里面没有什么惊天动地的新算法。读写分离、分层缓存、断路器、功能开关——全是基础的东西。但它们被创造性地组合到了 AI 场景里，打造出了这个时代最好的编程 Agent 之一。**

在一个连 IDE 都在 AI 化的时代，最值钱的能力可能不是「会用多少框架」，而是「理解底层原理」——

- 理解上下文窗口，你才知道为什么 Cluade Code 会「变笨」以及怎么管理它
- 理解 ReAct 循环，你才看得懂 LangGraph、AgentScope 这些框架本质上在做什么
- 理解分层缓存，你才明白 Claude Code 的记忆系统为什么设计成索引 + 按需加载
- 理解断路器，你才懂得上下文压缩策略里为什么要有熔断机制

:::warning
警惕「工具依赖症」：今天 Claude Code 最强，明天可能就有更强的。把时间花在理解 Agent 的本质、理解工程思想上，而不是背诵某个工具的操作步骤上。**越理解原理，越能驾驭工具。**
:::

## 八、总结：从「会用」到「理解」

回顾这一路，我们从「装一个 Claude Code 做番茄钟」开始，到「看懂它的源码架构和工程设计」结束。

如果你只带走三件事：

1. **会用**：掌握三种模式切换、CLAUDE.md 配置、/compact 压缩——这三样能覆盖 80% 的日常场景
2. **会管**：Git 兜底 + 上下文监控 + 记忆管理——让 Agent 稳定输出不翻车
3. **会理解**：LLM Loop、ReAct、分层记忆、五级压缩——懂原理才能用好工具

```text
从"会用"到"理解"的旅程：
┌──────────┐   ┌──────────┐   ┌──────────┐
│  装起来   │ → │  用起来   │ → │  理解它   │
│  （上手） │   │  （实战）  │  │  （源码）  │
└──────────┘   └──────────┘   └──────────┘
                     ↓
              驾驭它，而不是被它驾驭
```

正如我在「[编程生涯：AI 大模型认知之旅](../编程生涯ai大模型认知之旅/)」结尾写的：**AI 不是魔法，是工程。理解它，才不会被它「魔法」地忽悠。**

Claude Code 是工程的最好例证——它不是什么黑科技，而是一群优秀的工程师，把经典的计算机思想用在了 AI 这个新场景里。而我们能做的，就是保持对「它为什么好用」的好奇心，把这份理解变成自己的竞争力。
